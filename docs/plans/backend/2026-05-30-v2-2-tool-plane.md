# V2-2 Tool Plane

- 类型：实施计划
- 日期：2026-05-30
- 状态：已完成
- 关联：[CHANGELOG](../../CHANGELOG.md)、[V2-1 DeepSeek Gateway](2026-05-30-v2-1-deepseek-gateway.md)

## 目标

建成 V2 工具执行平面：schema 校验、工作区安全、权限决策、审批请求、注册元数据、内置文件/搜索/进程/网络/记忆工具，并经内核暴露。

## 结果

`src/tools`、`src/workspace`、`src/security` 落地为独立模块，没有照搬 V1 `tool-registry.js` 单体。所有工具调用走同一条 `ToolExecutor` 路径。执行顺序固定为规范化输入、校验 schema、从注册定义推导类别、权限决策、发审计事件，然后执行或请求审批。agent runtime 本阶段还不做完整的模型/工具多轮回环；V2-2 只暴露 `kernel.tools.execute()` 并发规范事件，方便 V2-4 干净接入迭代反馈。

### 范围

做：

- `src/tools` registry、schema 校验、executor、审批请求生成、builtin 定义。
- `src/tools/permissions` 权限引擎、policy context、approval cache。
- `src/workspace/path-safety.js` realpath 工作区边界。
- `src/security/shell-policy.js`、`src/security/ssrf.js`、`src/security/redactor.js`。
- 内置工具：`read`、`ls`、`grep`、`glob`、`shell`、`test`、`git`、`web_fetch`、`memory`、`task`、`ask_user`，以及延迟编辑工具 `edit`、`diff_preview`、`diff_apply`、`diff_rollback`。
- `src/index.js` 暴露 `kernel.tools.list()` 与 `kernel.tools.execute()`。
- 执行发布 `tool:call`、`permission:decision`、`approval:requested`、`tool:result`。
- 脚本集成进 `npm.cmd test` / `npm.cmd run check`。

不做：

- 真实 diff 应用与回滚记录（V2-3 的 `src/edits`）。
- DeepSeek tool-call 多轮回灌（V2-4）。
- CLI/TUI/GUI 迁移。
- JavaScript 插件执行；V2 只保留 wrapper 风格 builtin。

### 模块职责

| 路径 | 职责 |
|------|------|
| `src/workspace/path-safety.js` | realpath 工作区边界、文本读取上限、递归遍历。词法与符号链接逃逸都拒绝。 |
| `src/security/shell-policy.js` | shell argv 校验与 cwd 解析。后续 V2-17 扩展出共享 `runProcess`。 |
| `src/security/ssrf.js` | URL 与 DNS 校验，含每个 redirect 目标。 |
| `src/security/redactor.js` | 保守密钥脱敏，用于工具输出与事件。 |
| `src/tools/schema.js` | 内置工具用的最小 JSON-schema 风格参数校验。 |
| `src/tools/registry.js` | 工具定义存储、`toDeepSeekTools()` 导出、`secureToolCall()` 共享风险推导。 |
| `src/tools/executor.js` | 唯一执行入口；禁止旁路。 |
| `src/tools/permissions/permission-engine.js` | `DEFAULT_POLICY_MATRIX` 与 `decide` / `explain`。 |
| `src/tools/permissions/policy-loader.js` | `createPolicyContext`，组装 autonomy、trustStore、projectRules、approvalCache。 |
| `src/tools/permissions/approval-cache.js` | 指纹级审批缓存与 `grant()`。 |
| `src/tools/builtin/*` | 一组职责一个内置工具；`index.js` 聚合 `createBuiltinTools`。 |

### 工具清单与类别

| 工具 | 典型类别 | 说明 |
|------|----------|------|
| `read` | `read` | 读文件，受 path-safety 限制 |
| `ls` | `read` | 列目录 |
| `grep` | `read` | 内容搜索，可带超时 |
| `glob` | `read` | 路径模式匹配 |
| `shell` | `execute` | 只接受结构化 `argv`，`shell: false` |
| `test` | `execute` | 测试命令探测/执行 |
| `git` | `read` + `side_effect: "process"`（后续诚实标注） | git 查询 |
| `web_fetch` | `network` | SSRF 校验后的 HTTP |
| `memory` | 读 `read`；写/删动态 `write_update` / `write_delete` | 项目记忆 |
| `task` | 流程向 | 任务拆解辅助 |
| `ask_user` | 流程向 | 向用户提问 |
| `edit`、`diff_preview`、`diff_apply`、`diff_rollback` | 写向 | V2-2 注册可见；调用时因缺 `editService` 返回清晰错误 |

`createBuiltinTools({ editService, webFetch })` 在 V2-2 允许 `editService` 为空，延迟编辑工具只暴露元数据与失败语义，不假装可写文件。

### 权限矩阵（当时锁定）

类别 8 项：`read`、`read_secret`、`write_create`、`write_update`、`write_delete`、`execute`、`network`、`destructive`。

| 自治档 | read | read_secret | write_create | write_update | write_delete | execute | network | destructive |
|--------|------|-------------|--------------|--------------|--------------|---------|---------|-------------|
| supervised | allow | ask | ask | ask | ask | ask | ask | deny |
| gated | allow | ask | allow | allow | ask | ask | ask | deny |
| auto | allow | ask | allow | allow | allow | allow | ask | deny |
| full-auto | allow | ask | allow | allow | allow | allow | allow | deny |

`destructive` 在信任规则之前硬拒绝，命中 `hardcoded:destructive`、`source: "safety-invariant"`。

决策优先级（`permission-engine.decide`）：

1. `category === "destructive"` 硬拒绝。
2. `context.approvalCache` 指纹命中且 `decision === "allow"` → `matched_rule: "approval-cache"`。
3. `context.trustStore.rules` 命中 → `source: "user-trust-store"`。
4. `context.projectRules` 命中（跳过 `escalate_only`）→ `source: "project-rules"`。
5. `DEFAULT_POLICY_MATRIX[autonomy]`，未知 autonomy 回退 `gated`；未知类别回退 `ask`。
6. 风险提示只做单向升级：默认 `allow` 且命中 risk cue 时升为 `ask`（`risk-experience:escalate`），不降级 `deny`/`ask`，不覆盖显式用户决策。

后续 V2-17 增加 `read-only` 档，代码再扩 `execute_dangerous` 类别，以 `src/tools/permissions/permission-engine.js` 为准。

`createPolicyContext` 输入包括 `autonomy`、`trustStore`、`projectRules`、`approvalCache`、工具指纹所需上下文。`explain()` 在 decide 结果上补 `reason` 字符串。

### 内核暴露与事件

| API | 行为 |
|-----|------|
| `kernel.tools.list()` | 内置工具元数据 |
| `kernel.tools.schemas()` | DeepSeek 兼容 function tool schemas |
| `kernel.tools.execute(toolCall, ctx)` | 只经 `ToolExecutor` |

执行事件：

| 事件 | 何时 | 载荷边界 |
|------|------|----------|
| `tool:call` | 进入执行路径 | 工具名、参数摘要、来源 |
| `permission:decision` | 权量判定后 | decision、matched_rule、source |
| `approval:requested` | 决策为 `ask` | 审批请求与工具指纹 |
| `tool:result` | 执行结束 | status、content、metadata；含 `approval_required` |

工具输出经 `redactor` 脱敏后进入 content 与事件。

### 安全不变量

- 工具类别只来自注册定义或 `resolveCategory()` / `secureToolCall()`，模型输入里的 `category`、`risk_level`、`side_effect` 不能降级风险。
- `read_secret` 在所有自治档默认 `ask`。
- `shell` 只接受结构化 `argv`，始终 `shell: false`；拒绝原始命令字符串。
- 文件系统工具不能经词法路径或符号链接逃出项目根；`resolveWorkspacePath` / `mustExist` 约定在 path-safety 统一。
- `web_fetch` 校验协议、主机名字面量、DNS 结果与每个 redirect 目标；拦截 localhost、私网、IPv4-mapped IPv6、IPv6 字面量、file URL 与 DNS rebinding。
- `memory` 写/删动态映射 `write_update` / `write_delete`，不把删除伪装成读。
- 工具输出对常见密钥形态脱敏。
- 编辑工具在 `editService` 缺失时返回清晰错误，不静默成功。
- 任何工具都不得绕过 schema 校验与权限检查。

### 验收锁定清单（当时完成标准）

- `kernel.tools.list()` 返回内置工具元数据。
- `kernel.tools.schemas()` 返回 DeepSeek 兼容 function tool schemas。
- `kernel.tools.execute()` 跑 `ToolExecutor`，无旁路。
- 模型提供的 `category` / `risk_level` / `side_effect` 不能降级注册风险。
- `destructive` 在信任规则前拒绝。
- `read_secret` 各档默认 ask。
- shell 拒绝 raw command，只用结构化 argv。
- 文件系统工具不能词法或 symlink 逃出项目根。
- `web_fetch` 拦 localhost、私网、IPv4-mapped IPv6、IPv6 字面量、file URL、DNS rebinding。
- memory 写删用动态类别。
- 编辑工具在 V2-3 前返回清晰错误。
- 执行发布 `tool:call`、`permission:decision`、按需 `approval:requested`、`tool:result`。
- 工具输出脱敏。
- `npm.cmd test` 与 `npm.cmd run check` 通过。

## 关键决策 / 遗留约束

| 决策 | 选择 | 否决 | 原因 |
|------|------|------|------|
| 平面形态 | 干净 V2 模块 | 复制 V1 单体 | 职责清晰，安全规则集中 |
| 类别来源 | 注册定义 | 信任模型字段 | 防降权 |
| shell 形态 | 结构化 argv + `shell:false` | 整串命令 | 防注入 |
| 编辑工具 | 先占位再接线 | 本阶段假装可写 | 写路径要等 V2-3 成熟 diff 管线 |
| 插件 | 不做 JS 插件执行 | 动态加载 | 发布面可审计 |
| 模型回环 | 本阶段只暴露 execute | 直接连 DeepSeek | V2-4 专责迭代循环 |
| SSRF | 校验 DNS 与 redirect | 只看 URL 字符串 | 防 rebinding 与跳转绕过 |
| 风险升级 | 单向 allow→ask | 双向覆盖 | 不推翻用户明确决策 |

遗留约束：

- 不改 legacy `src/kernel/tool-registry.js` 与 `src/kernel/permission-engine.js`。
- 网络测试注入 `fetchImpl` 与 `lookup`，保持离线。
- 不加依赖。
- Windows 命令统一 `npm.cmd`。
- 无关脏文件保持不动。
- 不连接 DeepSeek 模型循环到工具执行。
- 不实现真实 diff 应用。
