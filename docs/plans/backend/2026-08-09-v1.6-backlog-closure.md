# v1.6 挂账清零实施方案

- 类型：实施计划
- 日期：2026-08-09
- 状态：已完成
- 关联：[agent 审计补救计划](../../specs/backend/2026-07-12-agent-findings-remediation.md)、[v1.6.3 design](../../specs/backend/2026-08-09-v1.6.3-agent-runtime-refactor-design.md)、[前端片](../frontend/2026-08-09-sensitive-file-warning-and-display-redaction.md)、[CHANGELOG](../../CHANGELOG.md)

## 目标

清空 [agent 审计补救计划] 遗留的 #9.3 / #10，外加 v1.5.1 审查新发现的「repair 阶段预算不计」。

## 结果

按 v1.6.1 → v1.6.2 → v1.6.3 顺序落地纯后端三片。分支 `feat/v1.6`，每片一个完整提交，发布后合入 `main` 并打 tag。

**排序理由**：#10 阶段 1 是补行为刻画测试锁住当前行为。若先做 #10，会把 repair 预算不计这个缺陷当作「当前行为」锁进测试；等再修它时刻画测试全要改，刻画测试的意义就没了。所以所有会改变 runtime 行为的补丁必须排在 #10 之前。

**v1.6.1 repair 阶段预算计入**：`agent-runtime.approve()` 四条分支中，只有普通工具那条曾持有预算对象（v1.5.1 已修续扣）。`runRepairLoop` 参数表加 `budget`，透传给 executor，循环顶部 `exceeded()` 早退；`repair-executor` 接 `budget`，`invoke` 后 `recordModelResult`；`agent-runtime` 的 `verifyAndMaybeRepair` 与 approve 路径两处传参。`budget = null` 时逐字节不变。定级为 patch：改变行为（此前无限的 repair 现在会被掐停），方向是让已文档化的护栏真正生效。

**v1.6.2 #9.3 后端卫生三件**（展示层脱敏与敏感文件提醒不在本片）：

1. **保留期/数量上限**：`config.edits.changeRetention = { maxRecords: 200, maxAgeDays: 90 }`，`finalizeChange` 成功后确定性清理（按 `time` 排序，超出者删）。清理只删记录，不碰工作区文件。
2. **大小上限 + 堵回滚清空洞**：超 `maxCaptureBytes`（默认 1 MiB）的文件只存 `sha256` + `truncated: true`，不存全文。必须同时堵的洞：`rollbackChange` 写的是 `file.before ?? ""`，截断记录若不拦会把用户文件清空。引入截断的同一片里让它对 `truncated` 记录抛 `ROLLBACK_TRUNCATED` 而非静默写空。
3. **目录限权**：`.deepseek-code/changes/` 创建时 `0o700`。Windows 上 `fs.chmod` 基本无效，这条只在类 Unix 生效，文档不得含糊。

**v1.6.3 #10 阶段 1–2**（阶段 3–4 定级再议）：阶段 1 为四条 approve 分支、事件发布顺序、错误语义补足端到端刻画断言，不改实现，只把当前行为钉死。此时 v1.6.1 已把 repair 预算修好，刻画的是正确的行为。阶段 2 产出职责/依赖边界 design：列出纯函数（状态迁移决策、`resume_state` 组装）与副作用（发事件、写 sidecar），标出四条恢复分支的公共「暂停–保存–清理」样板重复位置。阶段 3–4 维护者 2026-09-15 拍板延后到大版本：补丁/小版本不做结构重构。

**延后项留档**：敏感文件独立风险提醒（副作用告知，独立于权限档位，红色标注）与展示层脱敏（CLI `changes` / GUI `ChangeDiffView`）需三端前端配合，已开[前端片](../frontend/2026-08-09-sensitive-file-warning-and-display-redaction.md)，目标 v1.7.0。`changeRetention` 生产接线在 v1.7.1 完成（`config.edits` 进 DEFAULT_CONFIG 并注入 kernel → editService）。

## 关键决策 / 遗留约束

- **kernel 公开契约不变**：`send`/`approve`/`interrupt` 签名、事件发布顺序、错误语义（`code` / `message`）、审批暂停–续跑时序一律不得改变。阶段 3–4 开工时验收看边界清晰度与测试可独立性，不看行数。
- **变更记录存储内容一字节不动**：`rollbackChange` 依赖 `file.before` 原样写回。任何改动存储内容的方案都会破坏回滚。
- **刻画测试必须在 v1.6.1 之后写**。验收（必须实际做）：故意改坏实现任一处，确认至少一条刻画测试变红；改坏仍全绿就是没刻画到，退回重写。
- 敏感文件提醒设计立场：用户知情自己拍板，不是替用户挡住或放行。两条硬要求：独立于所有权限档位之外（副作用告知，非动作授权）；红色显著标注，三端各自实现。full-auto 建议拒绝该文件编辑并诚实上报；每次提醒不缓存；判定复用 `contextSkipReason`。
- 版本四处同步 `package.json` / `package-lock.json` / `src/theme.js` / `gui/src/App.jsx`，并打带注解 tag。提交信息不带 `Co-Authored-By`。
- 技术栈 Node ≥20 原生 `node:test`，零运行时依赖。
