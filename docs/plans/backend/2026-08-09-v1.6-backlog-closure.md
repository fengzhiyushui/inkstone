# 延后项设计要点(留档,勿在本轮实现)

## 敏感文件独立风险提醒

**要解决的问题:** agent 改 `.env` / `*.pem` / `*.key` 等文件时,该文件的**完整原文**会被抄进 `.deepseek-code/changes/<id>.json`(回滚必需,不可脱敏 —— 见 #9.3 硬约束)。用户对此**毫无感知**。

**设计立场(维护者定):** 这不是"替用户挡住"或"替用户放行"的事,而是**用户自己该知情、自己该拍板**的事。

**两条硬要求:**

1. **独立于所有权限档位之外。** 现有权限矩阵管的是「agent 能不能做这个动作」;本提醒告知的是「这个动作会在磁盘留下一份你看不见的密钥副本」—— 属**副作用告知**,不是动作授权。若混进权限档位,`auto` / `full-auto` 会一键放行,恰好绕过最该提醒的场景。
2. **红色显著标注**,三端(CLI / TUI / GUI)各自实现,不复用普通审批卡片的样式。

**允许 → 继续(并受本轮 v1.6.2 的卫生措施约束);不允许 → 不改这个文件。**

**待定的设计细节(前端片开工前需拍板):**

- **无人值守怎么办?** 若提醒在 `full-auto` 下也一律阻塞等待,无人值守的长任务会卡死。两个候选:(a) 一律阻塞(最安全);(b) `full-auto` 下不阻塞、直接**拒绝该文件的编辑并诚实上报**,把选择权留给下一次有人在场时。**建议 (b)**,理由是它既不卡死也不静默落盘。
- **记不记住选择?** 若走审批缓存,就等于把"独立于权限之外"又拉回权限体系。建议**每次都提醒,不缓存**。
- **判定来源:** 直接复用已导出的 [`contextSkipReason`](../../../src/context/workspace-indexer.js#L85),不新建清单。

# 补丁一 · v1.6.1 —— repair 阶段预算计入

## 背景(实测认定)

`agent-runtime.approve()` 四条分支,**只有「普通工具」那条持有预算对象**:

| 分支 | 入口 | 预算 |
|------|------|------|
| 普通工具审批 | [agent-runtime.js:313](../../../src/core/runtime/agent-runtime.js#L313) | ✅ v1.5.1 已修续扣 |
| repair 期验证器审批 | `resumeRepairVerifierApproval` | ❌ 无 |
| runtime 验证器审批 | `resumeRuntimeVerifierApproval` | ❌ 无 |
| repair 期工具审批 | [:371](../../../src/core/runtime/agent-runtime.js#L371) → `runRepairLoop` | ❌ 无 |

根因:[`runRepairLoop`](../../../src/core/verification/repair-loop.js#L5-L26) 参数表里**根本没有 `budget`**,而 [`repair-executor.js:24`](../../../src/core/execution/repair-executor.js#L24) 会实打实调 `modelGateway.invoke`。

**后果:** `maxTurnTokens` 文档承诺「单个 turn 的 token 上限」,但进入 repair 的回合,repair 期模型调用完全不计入 —— 护栏在最容易失控的路径上失效。

**定级说明:** 这**改变行为**(此前无限的 repair 现在会被掐停),但方向是「让已文档化的护栏真正生效」,与 v1.5.1 修超时同性质,按 patch。

## 文件

- 修改:`src/core/verification/repair-loop.js` —— 参数表加 `budget`,透传给 executor,循环顶部查预算
- 修改:`src/core/execution/repair-executor.js` —— 接 `budget`,`invoke` 后 `recordModelResult`
- 修改:`src/core/runtime/agent-runtime.js` —— `verifyAndMaybeRepair` 把 `budget` 传下去(send 路径与 approve 路径两处调用点)
- 测试:`tests/unit/core/runtime/agent-runtime-budget.test.js`(追加)

## 接口

- 消费:`createCostBudget()` 的 `{ recordModelResult, exceeded, snapshot }`(已存在,不改)
- 产出:`runRepairLoop({ ..., budget = null })` —— **`null` 即今日行为**,保证未注入时逐字节不变

## 步骤

- [ ] 1. 写失败测试:repair 期模型调用计入预算,预算耗尽后 repair 不再调模型
- [ ] 2. 跑到失败(预期:repair 无视预算继续调,`invokeCount` 超出)
- [ ] 3. 最小实现:executor `recordModelResult` + repair-loop 顶部 `exceeded()` 早退 + agent-runtime 两处传参
- [ ] 4. 跑绿 + 全量回归不得有旧用例变红
- [ ] 5. 补「不注入 budget 时逐字节不变」测试(裸调 `runRepairLoop` 不传 budget)
- [ ] 6. 文档:`project-overview` §7 护栏表补注「repair 期模型调用同样计入」;CHANGELOG
- [ ] 7. 版本同步 1.6.1 + 提交 + tag

# 补丁二 · v1.6.2 —— #9.3 后端卫生三件

> 展示层脱敏与敏感文件提醒**不在本片**(见「延后项」)。本片只做不碰前端、不碰回滚语义的部分。

## 背景

[`captureChangePlan`](../../../src/changes.js#L6-L34) 抄下每个被改文件的 **before 全文**,[`finalizeChange`](../../../src/changes.js#L36-L52) 再补 **after 全文**,整体落 `.deepseek-code/changes/<id>.json`。

**硬约束:** [`rollbackChange`](../../../src/changes.js#L79-L96) 靠 `file.before` 原样写回。**任何改动存储内容的方案都会破坏回滚。** 故本片一个字节都不动存储内容,只做卫生。

## 三件事

### ① 保留期 / 数量上限(今天完全真空)

实测:`listChanges` 只读不删,**全仓无任何 prune / TTL / 上限**。记录永久累积。

新增 `config.edits.changeRetention = { maxRecords: 200, maxAgeDays: 90 }`,在 `finalizeChange` 成功后做一次确定性清理(按 `time` 排序,超出者删)。**清理只删记录,不碰工作区文件。**

### ② 大小上限 + 堵回滚清空洞

超 `maxCaptureBytes`(默认 1 MiB)的文件只存 `sha256` + 标 `truncated: true`,不存全文。

**必须同时堵的洞:** 现行 `rollbackChange` 写的是 `file.before ?? ""` —— 截断记录若不拦,回滚会把用户文件**清空**。引入截断的同一片里必须让它对 `truncated` 记录抛 `ROLLBACK_TRUNCATED` 而非静默写空。

### ③ 目录限权

`.deepseek-code/changes/` 创建时 `0o700`。**如实说明:Windows 上 `fs.chmod` 基本无效**,这条只在类 Unix 生效,文档不得含糊。

## 文件

- 修改:`src/changes.js` —— 截断分支、`rollbackChange` 守卫、保留期清理、`mkdir` 权限位
- 修改:`src/config.js` —— `DEFAULT_CONFIG.edits = { maxCaptureBytes, changeRetention }`
- 测试:`tests/unit/changes-capture-limit.test.js`(新)、`tests/unit/changes-retention.test.js`(新)

## 步骤

- [ ] 1. 失败测试:超限文件只存 hash、`truncated: true`、`before === null`
- [ ] 2. 失败测试:**回滚截断记录抛 `ROLLBACK_TRUNCATED`,而非把文件写空**
- [ ] 3. 跑到失败 → 实现 → 跑绿
- [ ] 4. 失败测试:超出 `maxRecords` / `maxAgeDays` 的旧记录被清理,且**工作区文件不受影响**
- [ ] 5. 跑到失败 → 实现 → 跑绿
- [ ] 6. 目录权限位 + 对应测试(类 Unix 断言,Windows 上 skip 并记日志)
- [ ] 7. 文档:补救 spec #9.3 标「后端部分 ✅,提醒与展示层脱敏挂前端片」;`project-overview` §4/§9;CHANGELOG
- [ ] 8. 版本同步 1.6.2 + 提交 + tag
