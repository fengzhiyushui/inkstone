### Task 1: #7 `classifyCommand` 分类器(TDD)

**Files:**
- Create: `src/security/command-policy.js`
- Create: `tests/unit/security/command-policy.test.js`

**Interfaces:**
- `classifyCommand(argv) → "safe" | "dangerous" | "forbidden"`;纯函数、零依赖、不 throw(空/非数组/非字符串元素 → `"safe"` 之外最保守可判定值:空 argv 返回 `"safe"` 由上游 normalizeShellParams 保证非空,防御性返回 `"dangerous"` 亦可,测试钉死所选行为)。
- 归一化:`argv[0]` → basename → 小写 → 剥 `.exe/.cmd/.bat/.com`。
- 清单(设计 §3.3):forbidden = `format`/`mkfs*`/`diskpart`/`bcdedit`/`dd`;dangerous = 删除类(`rm`/`rmdir`/`rd`/`del`)、系统级(`shutdown`/`reg`/`sc`/`schtasks`/`taskkill`)、`curl`/`wget`、`npm` 且 argv 含 `publish`、`git` 且 argv 含 `push` 且含 `--force`/`--force-with-lease`/`--delete`、包装 shell(`bash`/`sh`/`zsh`/`dash`/`cmd`/`powershell`/`pwsh`)、解释器带执行参数(`node`+`-e|--eval`、`python`/`python3`+`-c`、`ruby`+`-e`、`perl`+`-e`)。

- [ ] **Step 1:** 写失败测试:归一化(`C:\\Windows\\System32\\cmd.EXE` → dangerous;`Git.exe push --force` → dangerous;`rm.exe` → dangerous)、三类代表命令、`node` 无 `-e` → safe / 有 `-e` → dangerous、`npm install` → safe / `npm publish` → dangerous、`git push origin main` → safe、`git push --force-with-lease` → dangerous、`format` → forbidden、空参数防御行为。
- [ ] **Step 2:** 实现 `command-policy.js` 使测试全绿。
- [ ] **Step 3:** `npm test` 全量回归 + `npm run check`。

### Task 2: #7 `resolveCategory` 接线(shell + git)

**Files:**
- Modify: `src/tools/builtin/shell.js`、`src/tools/builtin/git.js`
- Create: `tests/unit/tools/command-policy-wiring.test.js`

**Interfaces:**
- shell def 增 `resolveCategory(params)`:forbidden → `"destructive"`;dangerous → `"execute_dangerous"`;safe → `"execute"`(现网默认,行为零变化)。
- git def:GIT_READ_OPS 维持 `"read"`;非 read → 对完整 argv(`["git", ...]`)跑 `classifyCommand`,映射同上(现网非 read 类别为基准,safe 时保持现网类别)。
- 引擎零改动依据:未知类别 → `matrix[category] || "ask"`(permission-engine.js:59)所有档位 ask;`"destructive"` 在 decide() 最前端 deny(36-38 行),**先于审批缓存**。

- [ ] **Step 1:** 写失败测试(经 `createToolExecutor` + `createPermissionEngine` 组装):
  - forbidden argv(如 `["format", "c:"]`)在 supervised/gated/auto/full-auto 四档位均 `denied`;预先塞审批缓存亦不可放行。
  - dangerous argv(如 `["cmd", "/c", "npm", "test"]`、`["rm", "-rf", "x"]`)在**四档位均** `approval_required`。
  - safe argv(如 `["node", "--version"]`)行为与现网矩阵一致(supervised/gated ask、auto/full-auto allow)。
  - git 工具:read 操作(`status` 等)不受影响仍 allow;`git push --force` → approval_required。
  - 审批通过后重放:approve → 缓存放行 dangerous(5 分钟精确参数语义不变)。
- [ ] **Step 2:** 实现接线使测试全绿;确认 registry.secureToolCall 对 `resolveCategory` 的调用点(registry.js:39)与 memory 工具先例一致。
- [ ] **Step 3:** 全量回归:重点看现有 shell/git/test 工具套件与 e2e(test 工具嵌套路径**不得**新增确认)。
