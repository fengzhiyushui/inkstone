## 1. 目标与范围

完成 `v1.18.0` 四个阶段任务（`R18-01` 至 `R18-04`）及安全审计加固：
- **R18-01**：请求级编排聚合预算（`RequestBudget` / `RequestScope`）、全角色出站记账、未知 usage 保底负债、全树取消与跨进程恢复续扣。
- **R18-02**：内置 `task` 工具真实子 Worker 委派、权限交集校验、`depth=1` 防递归、父子两级审批暂停与 `task-paused/` 跨进程恢复。
- **R18-03**：`repair-executor` 有界 tool-call 语法修复（`maxToolCallRepairs`）、整批预校验零前置副作用、跨审批与跨进程恢复计数保持。
- **R18-04**：跨模块联合验收（Chain A / B / C 与 B03 完整闭环）、文档基线同步与四处版本号收口。

**刻意延期的非目标**：
- 审计台账 `#10`（`agent-runtime.js` 阶段 3–4 大规模状态机与恢复策略拆分）继续延期至 `v2.0`，本版本仅做窄接口接线。

## 4. 回退与恢复记录兼容说明

- **独立提交边界**：本冲刺在 `codex/v1.18` 分支按模块拆分为独立可回退提交（R18-01 预算与取消 → 安全加固 → R18-03 修复期语法重试 → R18-02 真实 `task` 委派 → R18-04 联合验收与版本收口）。
- **回退顺序与持久化记录保全**：
  - 如需单独回退 `R18-02`，`.deepseek-code/v2/sessions/<projectId>/task-paused/` 下的 sidecar 不会被自动删除；旧版程序扫描父 `paused/<id>.json` 时若遇到未知状态可由用户经 `/recovery` 查看或手动清理，不破坏工作区源码。
  - 如需回退 `R18-03`，`paused/` 记录中的额外 `tool_call_repairs` 字段在旧版中会被安全忽略。
  - `R18-01` 的 `orchestration-paused/` 新字段（`unknownUsageTokens`、`fallbackTokensPerUnknown`）向后兼容；旧版未记账且带有限配额的记录按 fail-closed 门禁标为 `blocked_recovery` 并保留原文件。
