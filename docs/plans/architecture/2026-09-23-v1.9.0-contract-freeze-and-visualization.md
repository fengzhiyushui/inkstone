### P0 风险（本版不修，现网官方 API 下即出事）

1. **工具循环第二轮必 400**（#2）：iteration 0 恒走 plan 通道（thinking 开 + tools），assistant 消息带 `reasoning_content` + `tool_calls`；回传时丢弃 `reasoning_content` → iteration 1 请求带 tools 且历史缺该字段 → 协议 400。审批恢复 `resumeExecutorLoop`（`executor-loop.js:244`）同路径中招。**修复点仅 3 处、现有测试 mock 向后兼容。**
2. **默认模型 ID 已退役**（#1）：`deepseek-v4-flash` 非现行售卖 ID（V4.1-Flash 起官方名为 `deepseek-flash`）。默认值五处（`config.js:12,19,21`、`model-router.js:1-5`、`fim-client.js:3`）+ help 文案（`cli.js:358`）+ GUI `Composer.jsx:6-9` 的 `KNOWN_MODELS` 还是两个更老的死 ID（`deepseek-chat`/`deepseek-reasoner`，2026-07-24 已停用，GUI 下拉仍在向用户推荐）。
3. **think 通道采样控制失效**（#3）：temperature 静默无效；`reasoning_effort` 的 low/medium 被静默提升、none 不可用——effort 细粒度调节实际不可用。

### 关键约束（接触面清点结论，直接影响设计）

- **退役迁移只能精确键匹配**：模型 ID 是开放字符串（README/DEPLOYMENT 文档化支持 Ollama/vLLM/OpenRouter，示例形如 `deepseek-coder-v2:latest`），**绝不可照搬 v1.8.0 主题迁移的「未知→兜底」**（`theme-hub.js:6-11`），否则会把第三方端点用户的模型名改写成官方 ID，直接打断兼容端点。只做 `RETIRED_MODELS` 精确映射、未知一律原样、仅内存归一、不重写用户 config.json。
- **遥测数据已齐，契约只冻结一次**：cache hit/miss、reasoning tokens 已在 `usage` 子对象内随 `model:response` 发布（`executor-loop.js:60`）。E2 **不新增**这些顶层字段，只加 `reasoning`/`tps`/`session_id`/`latency_ms` 四个——M1 一次定稿，M4 只改值不改形。
- **`CONTEXT_WINDOW = 128000`**（`gui/src/state/metrics-view.js:5`）与新模型 1M 上下文不符：即使不改模型 ID，上下文用量条也会在 12.8% 处显示 100%。必须同版修。

### M1 · 契约冻结（A1 + E2 一次性定稿）

- **A1a**：`src/sessions/event-schemas.js`（新，零依赖手写校验器）：每类已登记类型一个 schema；`validateEvent(type,payload)→{ok,errors[]}`；schema ↔ 类型集合双向覆盖；运行期可选严格模式 `config.events.strictSchema`（默认 false，开启也只 warn 不抛错，热路径零风险）。
