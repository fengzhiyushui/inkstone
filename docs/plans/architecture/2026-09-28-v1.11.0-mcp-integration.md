## 一、 目标与里程碑分解

### 1.1 总体目标
在 `v1.11.0` 中为 Inkstone 构建首个原生外部扩展底座——**MCP (Model Context Protocol) 外部工具接入体系**。
坚守 Inkstone 核心架构的“零外部运行时依赖（Zero Runtime Dependencies）”原则与统一安全护栏要求，让 Agent 能够动态发现、挂载和安全调用外部数据库（PostgreSQL/SQLite）、开发者服务（GitHub/GitLab）、网络爬虫与本地文件系统等标准 MCP Server。

### 1.2 里程碑规划 (M1–M5)

| 里程碑 | 核心主题 | 涉及领域 | 核心产出 / 交付项 |
|---|---|---|---|
| **M1** | 协议与传输层实现 | `src/tools/mcp/` | 零依赖纯原生 JSON-RPC 2.0 客户端、Stdio 跨平台管道传输、进程生命周期防孤儿、协议初始化握手 (`initialize`) |
| **M2** | 宿主管理与动态工具注册 | `src/tools/` + `src/core/` | `McpHub` 多服务统一调度、`ToolRegistry` 动态装配扩展点、两级命名空间隔离 (`mcp__<server>__<tool>`)、DeepSeek Function Calling Schema 转换与执行桥接 |
| **M3** | 安全护栏与配置加载 | `src/security/` + `src/config.js` | 外部工具风险分类推导 (`READ` / `EXECUTE` / `DESTRUCTIVE`)、人工审批拦截、`autoApprove` 白名单、Cursor/Claude 同构 `mcpServers` 配置加载与校验 |
| **M4** | 三端协同与 GUI 可视化中枢 | `gui/` + `src/cli.js` + `src/apps/` | 升级 `gui/src/components/v4/SecondaryViews.jsx` 中 `McpView` 实装、Electron IPC 契约打通（服务启停/探活/日志/重连）、CLI `inkstone mcp` 运维子命令 |
| **M5** | 全量回归与收口发布 | 仓库全局 | 1325+ 全量测试回归、五道质量闸门验证、版本号四处同步 (`1.11.0`)、CHANGELOG 与项目文档发布收口 |

## 二、 关键设计约束与实施原则

1. **零外部运行时依赖（Zero Runtime Dependencies）**：
   - 核心运行时严禁 `npm install @modelcontextprotocol/sdk` 或其它第三方 JSON-RPC 库；
   - 仅使用 Node.js 20+ 原生模块：`child_process` (stdio 进程派生)、`readline` (Line Protocol 帧切分与粘包处理)、`events` (EventEmitter 消息分发) 与 `crypto` (ID 生成)。
2. **两级命名空间与字符安全归一化**：
   - 所有外部工具统一遵循 `mcp__<serverId>__<toolName>` 格式，彻底隔离内置工具与不同 Server 间的命名冲突；
   - 函数名强制校验正则 `^[a-zA-Z0-9_-]{1,64}$`，对非标字符进行安全替换，保障 DeepSeek API 兼容性。
3. **安全护栏统一收敛（No Bypasses）**：
   - 外部工具执行严禁直接绕过 `PermissionEngine`；
   - 包含写操作/变更操作推导为非安全操作，必须弹出审批卡片挂起等待人类授权；
   - 严格继承 `limits.toolCallTimeoutMs`（默认 60s），超时利用 `AbortController` 熔断。
4. **跨平台进程防孤儿保障**：
   - 外部进程通过 stdio 交互，生命周期绑定 `McpHub`；
   - Windows 环境下须支持进程树退出（`taskkill /F /T /PID` 或 Tree-kill 方案），确保主进程退出或服务重启时绝无孤儿进程驻留。
5. **Git 规范与版本铁律**：
   - 严格在 `feat/v1.11.0` 分支推进；
   - 严禁出现 `-m1`、`-m4` 等非标准版本后缀提交；
   - 根目录 `README.md` 严禁改动（大版本专用）。

## 三、 改动范围与八目录白名单

八目录定义：`src/core`、`src/deepseek`、`src/tools`、`src/edits`、`src/sessions`、`src/context`、`src/security`、`src/workspace`。

### 3.1 八目录授权修改白名单
1. `src/tools/mcp/`（**新增目录与模块**）：
   - `src/tools/mcp/jsonrpc-client.js`：原生 JSON-RPC 2.0 协议编解码与请求响应匹配管理；
   - `src/tools/mcp/stdio-transport.js`：子进程 Stdio 传输通道、缓冲行读取与进程生命周期管理；
   - `src/tools/mcp/mcp-client.js`：单个 MCP Server 客户端实体，处理握手、工具探测与执行转发；
   - `src/tools/mcp/mcp-hub.js`：多 MCP 服务宿主管理器，处理配置启动、探活、重启与并发销毁；
   - `src/tools/mcp/schema-converter.js`：MCP Tool Schema 到 DeepSeek Function Calling Schema 的清洗转换器。
2. `src/tools/registry.js`：
   - 暴露 `mountExternalTools(serverId, toolDefs)`、`unmountExternalTools(serverId)`、`isExternalTool(toolName)`，支持动态挂载与路由。
3. `src/security/permission-engine.js`：
   - 扩充外部工具安全级别推导逻辑 `inferToolCategory(toolName, toolDef)`，接入 `ApprovalCache` 与人工审批中断。

### 3.2 非八目录授权改动
1. `src/config.js`：
   - 增加 `mcpServers` 的 schema 校验、结构规范化与缺省字段补齐。
2. `src/index.js`（组合根）：
   - 在应用启动时根据配置实例化 `McpHub`，并与 `ToolRegistry` 和 `PermissionEngine` 关联装配；提供进程退出清理钩子。
3. `src/cli.js`：
   - 新增 `inkstone mcp [list|check|restart]` CLI 命令支持。
4. `gui/`（桌面客户端）：
   - `gui/main.js` & `gui/preload.js`：登记 `mcp:list`, `mcp:restart`, `mcp:toggle` 等 IPC 处理函数；
   - `gui/src/components/v4/SecondaryViews.jsx`：重构 `McpView`，实现服务卡片、健康状态灯、工具列表抽屉与交互按钮。
5. `tests/`：
   - 新增单元测试与集成测试套件。
6. `docs/`：
   - 登记与维护设计规格、实施计划与使用指南。

## 四、 分步实施计划

### 里程碑 M1：协议与传输层实现（JSON-RPC 2.0 + StdioTransport + McpClient）

- **任务 M1.1：JSON-RPC 2.0 协议客户端 (`src/tools/mcp/jsonrpc-client.js`)**
  - 实现标准 Request、Notification、Response 帧封装；
  - 维护基于递增消息 ID 的 `pendingRequests` Map，支持 Promise 返回、超时自愈与错误响应封装；
  - 支持 Protocol Error 标准码（`PARSE_ERROR = -32700`, `INVALID_REQUEST = -32600`, `METHOD_NOT_FOUND = -32601`, `INVALID_PARAMS = -32602`, `INTERNAL_ERROR = -32603`）。
- **任务 M1.2：跨平台 Stdio 进程传输通道 (`src/tools/mcp/stdio-transport.js`)**
  - 利用 Node.js `child_process.spawn` 启动外部进程（兼容 `npx`, `uvx`, `python`, `node` 等可执行程序）；
  - 利用 `readline.createInterface({ input: child.stdout })` 安全解析换行分帧，杜绝半包/粘包；
  - 监听 `stderr` 并收集最近错误日志缓冲区（最多保留 100 行，用于诊断展示）；
  - 封装跨平台优雅退出与强制终止（Windows 下执行递归清理，防孤儿进程）。
- **任务 M1.3：MCP Client 连接实体 (`src/tools/mcp/mcp-client.js`)**
  - 编排连接握手流程：发送 `initialize` 携带 clientInfo (`inkstone 1.11.0`) 与 protocolVersion (`2024-11-05`)；
  - 接收 Server 响应后发送 `notifications/initialized`；
  - 暴露 `listTools()` 发起 `tools/list` 请求；
  - 暴露 `callTool(name, arguments)` 发起 `tools/call` 请求并解析 `content`；
  - 异常隔离：单个请求崩溃或超时不影响 Client 状态，进程异常退出触发 `onError` 回调并标记状态。
- **M1 验证**：
  - 编写 `tests/unit/mcp-jsonrpc.test.js` 与 `tests/unit/mcp-stdio-transport.test.js`；
  - 使用 Mock Server 子进程（Node 简易回显脚本）跑通握手、工具列举、错误帧处理与进程生命周期。

---

### 里程碑 M2：宿主管理与动态工具注册（McpHub + ToolRegistry 动态装载）

- **任务 M2.1：多服务宿主管理器 (`src/tools/mcp/mcp-hub.js`)**
  - 统一持有所有已配置的 `McpClient` 实例，提供 `initAll()`, `stopAll()`, `restartServer(serverId)`；
  - 维护各服务状态机：`DISCONNECTED` -> `CONNECTING` -> `CONNECTED` -> `ERROR`；
  - 错误自愈与保护：某个服务启动失败时隔离记录，绝不阻断其他服务和主内核运行。
- **任务 M2.2：Schema 转换器 (`src/tools/mcp/schema-converter.js`)**
  - 命名空间命名转换：`formatExternalToolName(serverId, originalName)` -> `mcp__<serverId>__<originalName>`；
  - 反向解析：`parseExternalToolName(namespacedName)` -> `{ serverId, originalName }`；
  - Schema 清洗：将 MCP Tool 的 `inputSchema` 转化为符合 DeepSeek/OpenAI 函数调用的标准 JSON Schema（移除不支持的 meta 字段，补充 type 等）。
- **任务 M2.3：`ToolRegistry` 动态装载改造 (`src/tools/registry.js`)**
  - 扩展 `mountExternalTools(serverId, tools)`：将服务暴露的工具转为带有内部代理的执行对象，注入到注册表中；
  - 扩展 `unmountExternalTools(serverId)`：干净卸载指定服务的所有工具，不影响内置 12 工具；
  - 扩展 `isExternalTool(toolName)` 与 `describeTools()`，确保 DeepSeek 请求 payload 中正确包含动态挂载的工具。
- **任务 M2.4：执行分发与结果映射**
  - 内核工具执行层路由：若调用 `mcp__*` 工具，自动分发至 `McpHub.callTool(serverId, originalName, args)`；
  - 结果转换：将 MCP Server 返回的 `content: [{type: 'text', text: '...'}]` 拼接并标准化为字符串返回给 Agent 循环。
- **M2 验证**：
  - 编写 `tests/unit/mcp-hub.test.js` 与 `tests/unit/mcp-schema-converter.test.js`；
  - 编写动态装配测试 `tests/unit/mcp-tool-registry.test.js`，验证装载、列出、调用、卸载的完整生命周期。

### 里程碑 M3：安全护栏与配置加载（PermissionEngine 映射 + config.json mcpServers）

- **任务 M3.1：安全级别自动推导 (`src/security/permission-engine.js`)**
  - 实现 MCP 工具风险分类逻辑：基于工具名词义（`get/read/list/search/query` -> `ToolCategory.READ`，`create/update/delete/exec/mutate/write` -> `ToolCategory.EXECUTE` 或 `DESTRUCTIVE`）；
  - 支持配置级 `autoApprove` 覆盖：配置中声明白名单的工具视为受信任，无需重复审批。
- **任务 M3.2：拦截挂起与审批恢复集成**
  - 当 Agent 产生高危外部工具调用时，触发 `PermissionEngine.checkPermission()`；
  - 若需审批，发出 `approval:request` 事件，向用户呈报工具全名、所属服务与输入参数，主循环安全挂起；
  - 用户批准（`approve`）后继续投递执行，拒绝（`reject`）则向 Agent 返回权限拒绝提示。
- **任务 M3.3：配置体系扩展 (`src/config.js`)**
  - 增加 `mcpServers` 顶层配置节点解析，校验每一个 server 配置的 `command`, `args`, `env`, `disabled`, `autoApprove`；
  - 环境变量隔离：仅传递基础安全 PATH 与用户显式指定的 `env`，杜绝父进程的全局敏感环境变量静默泄漏给第三方工具进程。
- **M3 验证**：
  - 编写 `tests/unit/mcp-security.test.js`，验证只读放行、写操作挂起审批、`autoApprove` 白名单放行与环境变量防泄漏；
  - 编写 `tests/unit/mcp-config.test.js`，验证配置文件加载、错误容忍与默认值填补。

## 六、 风险应对与回滚策略

| 风险场景 | 影响 | 应对与回滚对策 |
|---|---|---|
| **外部 MCP Server 子进程崩溃或假死** | 导致 Agent 等待阻塞或报错 | 在 `StdioTransport` 强制应用请求级超时与心跳探活；发生故障时将对应服务置为 `ERROR` 并隔离，不影响其他工具与 Agent 主流程。 |
| **第三方工具参数 Schema 过于复杂或不合规** | DeepSeek API 报 400 错误 | 在 `SchemaConverter` 中增加强容错过滤逻辑，剥离 DeepSeek API 不支持的复杂 JSON-schema 校验属性（如 `patternProperties`, `dependencies`），安全折叠为通用 object。 |
| **Windows 平台子进程清理残留（孤儿进程）** | 占用端口或系统资源 | 在 Windows 上启动时使用独立进程组，并在退出时通过 `taskkill /pid <pid> /T /F` 或操作系统 Job Object 清除整个进程树。 |
| **外部工具引入高危注入或提权操作** | 威胁宿主系统安全 | 严格通过 `PermissionEngine` 与 `ApprovalCache` 强制进行前置推导与人类审批，且默认禁用环境变量直传。 |
