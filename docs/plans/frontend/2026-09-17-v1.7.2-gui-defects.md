# v1.7.2 GUI 缺陷补丁实施方案

- 类型：实施计划
- 日期：2026-09-17
- 状态：已完成
- 关联：[CHANGELOG](../../CHANGELOG.md) · [v1.8.0 工学换肤](2026-09-17-v1.8.0-ergo-restyle-plan.md) · [post-V3 路线图](../../specs/architecture/2026-09-17-post-v3-roadmap-design.md)

## 目标

修掉 v1.7.x GUI 三处缺陷，并补上 v1.7.0 欠下的敏感模态冒烟截图。纯 GUI 补丁，内核零改动；是 v1.8.0 卡片重排的硬前置。

## 结果

### 缺陷① agent 回复从不进消息流

证据：`workbench-state.js` 的 `event_received` 只处理审批 / 敏感提醒 / 错误类，没有 `agent:final`；`messages` 只在用户发送时 `message_added` 写入；`ChatView` 的 `.a-msg` 分支因此从未渲染。

修复：`agent:final` 且 `content` 为非空字符串时追加 `{ role: "assistant", text: content }`。字段名用 `text`（与 `App` 用户消息、`ChatView` 的 `m.text || m.content` 一致）。空 content 不追加；`status: "stopped"` 也入流，让用户看到截停原因。消息继续 `slice(-200)` 防长会话无界增长。

### 缺陷② 状态行数据首屏一次、永不刷新

证据：`buildInitialLoads` 只在 `useKernel` 挂载时跑一次；`onKernelEvent` 只 `dispatch(eventToAction(e))`，回合结束后不重拉 `getUsage` / `listCheckpoints`。

修复：`kernel-loads.js` 新增纯函数 `refreshLoadsFor(eventType)`。`TURN_END = { agent:final, agent:error, turn:cancelled, file:rollback_applied }` 命中时返回与 `buildInitialLoads` 同形状的 getUsage + listCheckpoints 两项；其余事件返回 `[]`（避免 `model:*` / `tool:*` 上每回合十几次 IPC）。`useKernel` 在事件回调里先 dispatch 再执行 refresh loads，`toAction` 仍为 `usage_loaded` / `checkpoints_loaded`，reducer 无需新 action。

### 缺陷③ 敏感模态引用未定义 CSS 变量

证据：`.sn-*` 规则引用 `--bg` / `--bg-1` / `--bg-2` / `--bg-3` / `--fg-1` / `--mut` / `--bdr`，在 `tokens.css` 与 `theme.css` 定义处均为 0，模态底色透明、文字无色。

修复映射：`--bg`→`--bg-base`，`--bg-1`→`--bg-panel`，`--bg-2`/`--bg-3`→`--bg-element`，`--fg-1`→`--text`，`--mut`→`--text-mut`，`--bdr`→`--border-strong`。新增 `tests/unit/gui/css-vars.test.js` 通用守卫：收集 `tokens.css` + `theme.css` 的定义槽位，扫描样式文件里每个 `var(--x)`，未定义即红（不止管 `.sn-*`）。后续样式迁回后仍覆盖 `theme.css`。

### 欠账④ 敏感模态冒烟截图

难点：模态由内核 push `gui:sensitive_notice` 触发，冒烟无 API Key 走不到真实编辑。解法：主进程直接向渲染层 push 构造事件（走 `kernel:event`，即 `pushEvent` 已有通道，不加新 IPC）。

smoke 链在 `.settings-back` 之前插入：回首页 → push 带 `request_id` / `descriptor`（kind `sensitive-file-write`、paths `.env` + `secret-file`、recordDir）的事件 → 截 `shell-sensitive-notice` → 点 `.sn-refuse` 关闭。未知 id 经 `respondSensitive` → `sensitive:respond` → `resolveSensitiveNotice` 静默 `false`，不挂主进程。

截图曾复制到 `docs/prototypes/v1.8.0-ergo-restyle/screenshots/v1.7.2-sensitive-notice.png` 入库（现已清理；`gui/__screenshots__` 仍被 gitignore）。
