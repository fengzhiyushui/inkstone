## 1. 现状摸底(2026-07-31 实测,方案的事实基础)

### 1.1 GUI(`gui/`,≈3.2k 行)

| 事实 | 对方案的意义 |
|---|---|
| **独立 `gui/package.json`,已带 React 19 + Electron 30 + Vite 7 + Monaco + xterm + node-pty**;根 `package.json` 依赖为空 | "零依赖红线"只约束主包,GUI 壳层**本来就有依赖**——技术栈疑问就地解决:**沿用 React + Vite,不引入新 UI 框架** |
| 现渲染层是 **VS Code 式 IDE**(ActivityBar / Explorer / EditorGroup / StatusBar / Terminal),入口 `App.jsx` | 终稿是**会话优先**的 Codex/Claude Desktop 形态——不是改样式,是**信息架构换血**,渲染层重写比改造便宜 |
| 状态层(`gui/src/state/*` 13 个纯函数模块)与展示层分离,**20 个单测全部押在状态层与 kernel-host 上**,React 组件零单测 | 重写渲染层**不动大部分测试资产**;新增状态模块沿用同一模式(纯函数 + node:test) |
| `preload.js` 白名单 ≈35 个 IPC 通道;`kernel-host.js`(482 行)单例 kernel,root 由启动参数定死,**一进程一会话** | 会话列表/切换、项目切换都是**新的宿主层生命周期能力**;`createKernel({ root })` 本就按 root 实例化,重建 kernel 即可切换,**kernel 零改动可行** |
| 主题:`theme.css` 手写 2 套(dark/light,`body[theme-mode]`) | 换成 v4 `tokens.css` 的 10 套 `[theme="<id>"]` 机制,属直接替换 |
| v1.3.2 已删 `gui/renderer/` 休眠副本(审计 #5:事件→展示并行实现是事故源) | **禁止"新旧渲染层并存"的迁移策略**——原地替换,git 历史即回滚手段 |

### 1.3 数据与能力空洞(决定方案边界)

| 探查项 | 实测结果 | 结论 |
|---|---|---|
| 会话落盘 | `<root>/.deepseek-code/v2/sessions/proj_<hash>/sess_*.jsonl`(+ `.branches.json`),**本项目实测 6+ 个可枚举** | **会话列表有数据基础**——枚举目录即可,无需 kernel 改动 |

## 2. 技术决策(定案,除非实施中被事实推翻)

1. **GUI 技术栈不换**:React 19 + Vite 7 + Electron 30 原样沿用;不引 UI 组件库(终稿是自绘设计系统,组件库反而打架)。Monaco 保留给 diff 视图,xterm + node-pty 保留给内嵌终端。
2. **渲染层原地重写,宿主层增量扩展**:`gui/src/` 下 IDE 形态的组件按阶段替换为 v4 形态;`main.js` / `preload.js` / `kernel-host.js` / `pty-host.js` 只**增**通道与能力,不推倒。禁止并存两套渲染层(§1.1 教训)。
3. **v4 `tokens.css` 为唯一 token 源**:GUI 直接 `import`;TUI 经构建期脚本生成 256 色映射表(`scripts/gen-tui-theme.js` → `src/apps/tui/theme-palette.js`,生成物入库,主包运行时仍零依赖)。
4. **kernel(`src/core|deepseek|tools|edits|sessions|context|security|workspace`)零改动**;所有新能力落 app/宿主层。安全不变量不动:密钥只见掩码、IPC 白名单逐通道显式声明。
5. **MCP / 插件 = 概念预览**:只有视图与空态文案,不接任何运行时;功能语义留待独立立项。
6. **TUI 仍零依赖手写 ANSI**;i18n 维持 zh/en、默认中文。
7. **版本定级 v1.4.0(minor)**:kernel 不动、无破坏性契约变更,符合命名规则"大版本规划内的功能实现"。

## 5. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | **项目切换 = 重建 kernel**,在途回合/订阅泄漏 | kernel-host 增 `disposeAndRecreate(root)`:先 interrupt + flush + unsubscribe 再重建;切换期间 UI 上锁;单测覆盖重建路径 |
| R2 | **"打开旧会话"越界风险**:kernel 无"续写既有会话"入口,硬造就要动 kernel | 保底交付 = **只读回放 + 「续聊」按钮开新会话**(带上一会话摘要作首条上下文);若实施中发现 `createKernel` 可无侵入指定 sessionId 再升级,**不为此改 kernel** |
| R3 | 渲染层重写期间分支不可用 | 阶段边界必须绿(测试 + smoke);P1 未收口前不删旧组件文件,收口时一次移除(避免半新半旧) |
| R4 | TUI 256 色在低端终端失真 | 生成物含 16 色降级列;`NO_COLOR` 全禁路径回归测试 |
| R5 | Windows shell 宏路径差异(git-bash 安装位不定) | `/shell` 检测可执行文件存在性,缺失项灰显;pty-host 单测枚举四宏 |
| R6 | 工期膨胀 | 阶段可独立发布:P0+P1+P4 即可出 v1.4.0,P2/P3 顺延到 v1.4.x 由用户届时定 |
