## 3. 主题体系

### 3.1 问题:双峰分布

现行 10 套按底色亮度排:`mocha 25 · rose 25 · sumi 32 · moon 33 · clay 40 · forest 51 · nord 51 │ latte 240 · dawn 244 · paper 251`。**51 → 240 之间没有任何主题。** 用户原稿同样双峰(13–33 │ 236–251)。决策②要求填这段空白。

### 3.2 分档模型:四段连续带,中灰是物理死区

**先摆一个硬事实**(本 spec 撰写时用 WCAG 公式实测,公式已用 v1.4 记录的 forest 7.4 / sumi 11.3 / paper 16.7 三个值校验一致):

> 正文对比度闸门 **≥7:1** 决定了底色亮度有一段**死区**。灰底感知亮度 **L 90–164** 之间,**白字与墨字都做不到 7:1**——任何主题落在这段都过不了闸门。

| 底色亮度带(0–255 感知) | 可行性 | 说明 |
|---|---|---|
| L ≤ 89 | ✓ 白/浅字 | 白字最亮可到 `#595959`(L89)仍 7.1:1 |
| **L 90 – 164** | **✗ 死区** | "真正的中灰"物理上做不出合格主题 |
| L ≥ 165 | ✓ 墨/深字 | 墨字最暗可到 `#a5a5a5`(L165)仍 7:1 |

现行暗组占 L 25–51,明组占 L 240–251。所以"过渡色主题"**不能**理解为"中灰",只能是两侧向死区边缘**各自延伸**:

| 档 | 亮度带 | 定位 | 套数 |
|---|---|---|---|
| **暗 dark** | L 25 – 51 | 现行深色区(OLED / 夜间) | 3 |
| **柔暗 dim** | **L 55 – 89** | 暗侧过渡:比深色主题亮一到两档,减少夜间"黑洞感"——Zenburn / Gruvbox Soft / Nord Polar+1 这一族的调子 | 2 |
| **柔明 tint** | **L 165 – 235** | 明侧过渡:比白纸暗,有色相(暖沙 / 冷雾),减少白天"白炽感"——Gruvbox Light Soft / Nord Snow Storm / Sepia 阅读器这一族 | 2 |
| **明 light** | L 236 – 251 | 现行纸感白 | 3 |

**这才是"有过渡"在物理约束下的真实形态**:四段连续带,中间隔着一段谁也进不去的死区。用户感受到的是"从深到浅有 4 个台阶",而不是"两极 + 一个中灰"。

### 3.4 对比度闸门(继承 v1.4 §3.2,升级为常驻单测)

11 对 × 10 套 = 110 项:正文/画布与正文/面板 **[7, 19.5]**;次级 ≥4.5;弱化 / 强调 / ok / warn / err / info ≥3;按钮文字(accent-text/accent)≥4.5;描边(border-strong/bg-base)**≥1.5**(v1.4 只印实测未定阈值,本版钉为 1.5)。

**新增实现要求**:`scripts/check-theme-contrast.mjs`(解析 `tokens.css`,CLI 打印表格,任一不过 exit 1,导出纯函数)+ `tests/unit/gui/theme-contrast.test.js`(同一函数,断言 110/110)。v1.4 的闸门是一次性表格,以后谁改一个色值都不知道破没破;本版把它变成常驻测试——**这条价值超出 v1.8.0**。

### 3.5 分档对代码的影响(二元 → 四档,但明暗判定仍二元)

四档只是**展示分组**;代码里真正需要的判定只有一个——"这个主题是明还是暗"(Monaco 用 `vs`/`vs-dark`、标题栏 Moon/Sun、`lastDark`/`lastLight`)。规则:**dark + dim → 暗;tint + light → 明**,分界线就是死区。

| 位置 | 现状 | 改为 |
|---|---|---|
| `gui/src/state/themes.js` `group` | `"light" \| "dark"` | 新增 `tier: "dark" \| "dim" \| "tint" \| "light"`(展示用);`group` 保留二元并由 tier 派生(`dark/dim → "dark"`,`tint/light → "light"`);`isLightTheme()` 语义不变 |
| `gui/src/components/DiffView.jsx:7` `LIGHT` 集合 | 硬编码 3 个 id | 改为 `isLightTheme(theme) ? "vs" : "vs-dark"` 单源 |
| `TitleBar.jsx` Moon/Sun 键 | `sumi ↔ latte` 写死 | 「切到另一模式最近主题」(`lastDark`/`lastLight`);dim 归 dark 模式候选、tint 归 light 模式候选 |
| 设置›外观 | 一个 10 卡网格 | **四段分组**(暗 3 / 柔暗 2 / 柔明 2 / 明 3),每段带一行说明(亮度带) |

TUI 不分明暗,不受影响。`tokens.css` 槽位 18 个**名字不动**、块顺序 = UI 顺序(暗 → 柔暗 → 柔明 → 明)= TUI `/theme` 轮换顺序——**这个顺序本身就是"从深到浅的连续过渡"**,`/theme` 连按即可感受。

### 3.6 舒适性(决策④的落地,不是动效)

| 手段 | 具体 | 代价 |
|---|---|---|
| 正文对比度上限 19.5:1 | 已在闸门里——防"纯黑底纯白字"刺眼 | 0 |
| 字阶 | 保持 `--fs-11..18` 六级,**不出现 <11px**;行高 1.5–1.6 | 0 |
| 圆角 | 卡片 10–14px、胶囊 18px、按钮 6px,统一走 `--r-*` | 小 |
| 柔光 | 只在 **focus-within** 与 hover:composer `0 20px 50px -10px var(--accent-glow)`;卡片 hover 上浮 2px | 小,已有先例 |
| 留白 | 消息流 768px 居中;卡片间距 12px;侧栏分区 16px | 0 |
| 玻璃态 | **只给浮层**(菜单/模态/chat 内 composer),`blur ≤ 12px`,不 `saturate`;偏好 `glass` 默认开,`prefers-reduced-transparency` 关 | 小 |
| 蓝图网格 | **不做**——纯装饰(全屏 32px 细线格),零功能;默认关的装饰开关只剩维护成本(偏好键 + 设置行 + i18n + 选择器),与粒子层同一桶。维护者 2026-09-17 定 | — |
| 动效 | 只保留现有 `msgIn .22s` / `viewIn .18s`;新增一律 ≤ .25s 且 `prefers-reduced-motion` 关;**不加**粒子/视差/光标跟随 | 0 |

## 6. 为 β 留门(决策③)

β = 按原稿 deck/unit/head/body 解剖学重建全部标记为单文件 `studio.css` + 原语组件。γ 落地时**不得**做这些让 β 更难的事:

1. **不新造与原稿语义冲突的类名**:γ 新增的类名一律取自 gap-map 附录 1 的"现有 ↔ 原稿"映射表右列(`.tl-*` `.th-*` `.modal-*` `.ev-h/.ev-b`),β 时可直接对位替换。
2. **样式只加不删**:`shell.css` 新规则**追加在文件末尾独立区块**(`/* ── v1.8 γ ── */`),不改写既有规则的选择器;β 时整块可删。
3. **派生变量进 `theme.css` 别名块**,不进 `tokens.css` 主题块——β 若换 token 组织方式,tokens.css 仍是干净的 10×18。
4. **组件不新增 props 契约**:P2 的 ThoughtCard / ThemeHub 只消费已有 state 字段;β 重建时 props 面不变。
5. **偏好键一次定名**:`lastDark / lastLight / glass` 三键 β 沿用。

β 的触发条件(写下来,不再讨论):用户看完 γ 三层后仍觉得"只是换了主题和卡片"、要"打开就像原稿"→ 立 v1.8.x 或 v1.9 做 β,届时 smoke 基线与 dom-contract 一并重做。
