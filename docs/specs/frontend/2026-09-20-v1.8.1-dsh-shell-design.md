## 0. 先纠正一个前提

「参考 DSH 的前端界面,但不要 web 端,改成桌面端」——**DSH 已经是桌面端**。`apps/desktop` 是 Electron 44 + electron-builder,`apps/web` 只是它加载进 BrowserWindow 的 Vite 产物;Windows 上用 `titleBarStyle:'hidden'` + 40px 原生覆盖标题栏,macOS 用 `hiddenInset` + 侧栏 vibrancy。这和 Inkstone `gui/` 是**同一种东西**。

所以本版不是换平台,是**换壳层布局与视觉语言**。这正好落在 v1.8.0 spec §6 预留的 **β 路径**上:「用户看完 γ 仍觉得不好看 → 立 v1.8.x 做 β,届时 smoke 基线与 dom-contract 一并重做」。触发条件已成立。

**定级说明:** 用户叫它 v1.8.1。按 [版本规则](../../README.md#版本命名规则) 壳层 DOM 重排属「一次前端对齐」= minor,应为 **v1.9.0**;但路线图里 v1.9.0 已装了「契约冻结 + Inspector」。两个选项见 §8-Q1,本文暂用 **v1.8.1** 称呼。

## 3. 主题体系怎么办(本版最需要拍板的设计题)

DSH 只有明暗两套;Inkstone 刚在 v1.8.0 花了整版做 10 套四段带 + 110 项闸门。**两种做法不能都要**,但可以分层:

**方案 A · 模式 × 配色(建议)**:壳层结构色(侧栏底 / 主区底 / 描边 alpha / 阴影 / 圆角)走 DSH 的**中性蓝灰阶**,只分明暗;10 套主题降为「**配色 accent**」——只贡献 `--accent / --accent-hover / --accent-soft` 与语义色,不再各自定义 bg/text。结果:界面骨架统一像 DSH,用户仍可选 10 种强调色。闸门从 110 项缩到 10 × 4 对(accent 与语义色对中性底)。**代价**:v1.8.0 四段带的"过渡色"概念消失(bg 只有明暗两档)。

**方案 B · 全保留**:10 套各自 18 槽不动,只把 DSH 的布局/圆角/描边/阴影套上来。**代价**:DSH 的观感很大程度来自"冷蓝灰 + 单一蓝",套在 Kanagawa 色相上不像 DSH;等于 γ 再做一次。

**方案 C · 两套走 DSH,八套退役**:只留明暗两套(值直接取 DSH 阶梯),其余 8 套退役。最像 DSH,但推翻用户 v1.4「10 套」与 v1.8.0「四段带」两次定稿。

**2026-09-20 已定:C 变体**(维护者「尽可能全量搬」表态后 A 不再成立)——壳层 `bg-base/bg-panel/bg-element/bg-inset/text/text-mut/text-faint/border/border-strong/code-bg` 十个结构槽**全部**走 DSH 阶梯,只分明暗两档;10 个主题 id 保留,每个只贡献 `accent/accent-hover/accent-soft/accent-text/ok/warn/err/info` 八个槽。闸门口径:结构槽 2 档 × 7 对 + 每主题 4 对(accent/ok/warn/err 对 bg-base)× 10 × 2 档 = **94 项**。四段带退场;`tier` 字段保留仅作设置页分组标签。

### 4.0 移植原则:全量搬**设计**,零引用**代码**(维护者 2026-09-20 定)

维护者三条要求:① 与当前前端**结合适配**,② **不直接套用或引用 DSH 的库或函数**,③ **尽可能全量搬过来**。三者合起来的唯一解:

> **DSH 的设计全量搬——布局、尺寸、圆角、描边、阴影、色阶、动效时长、交互态,每一个数值都搬;DSH 的代码一行不搬——不 import 它的包,不复制它的源文件,每个组件与样式都在 Inkstone 现有结构上原生重写。**

所以「搬」的单位是**设计事实**(一个 px 值、一个 alpha、一条交互规则),不是文件。DSH 源码(`D:\dsh\deepseek-harness\packages\client`,MIT)只作**读取参照**,plan 里每条任务给出"读哪个 DSH 文件的哪几行取值",执行者据此写 Inkstone 自己的代码。

**"全量"的边界(哪些设计事实搬,哪些不搬)**:

| 类别 | 搬 | 依据 |
|---|---|---|
| 壳层布局:三列 grid、列宽常量(264/420/280/56/300/400/1024/0.45/0.7)、拖拽命中带 8px、折叠淡出 150ms、Windows 40px 标题栏 + 主区 16px 圆角 | **全搬** | `ui-layout/columns.ts` + `AppFrame.module.css` |
| 视觉 token:中性蓝灰阶(00/50/100/300/400/600/700/850/900/950/1000)、品牌蓝 `rgb(65,118,230)` 及其 hover/soft、alpha 描边 l1–l3、hover 8%、语义 green/amber/red-500、阴影 lv1/lv2、圆角 6/8/12/20/22、字号 12/13/14、行高 17/20/22、动效 0.1/0.2/0.3s + `cubic-bezier(0.4,0,0.2,1)` | **全搬** | `design-platform.css` + `base.css` + `gradient-shadow-text.css` |
| 滚动条皮(8px、alpha 滑块、`@supports not selector(::-webkit-scrollbar)` 双路径)、超椭圆圆角(`superellipse(1.5)`,`@supports` 守卫) | **全搬** | `scrollbar.css` / `corner-shape.css` |
| 首帧防闪:index.html 内联按偏好着色 + 窗口 `backgroundColor` 同步 | **搬思路** | `boot-theme.ts` |
| 侧栏:12px 内边距、品牌行、新会话钮、行 r8 / `0 8px` / hover=选中同色、56px 轨 36×36 控件 | **全搬** | `SidebarRoot.module.css` + `Rows.module.css` |
| 会话页:用户气泡 r22 / `10px 16px` / `max-width min(70.2%,82%)` 右对齐、助手无气泡、思考折叠行左竖线、消息块 gap 16、内容宽 `min(100%-32px, 920px)` | **全搬** | `MessageItem.module.css` + `ReasoningRow.module.css` + `ChatView.module.css` |
| composer:r22 卡、`input-major` 底、侧净空 16px、stats 行挂底、上下文圆环 | **全搬** | `InputBar.module.css` + `ContextMeter.module.css` |
| 会话头:标题 + 模式胶囊 + 更多 + 右栏开关 + `对话/轨迹` tablist | **全搬布局** | `ConversationSession.tsx` 结构 |
| 右栏 dock:tab 条、面板槽、0.5px seam、关闭钮、`role=tablist/tab` | **全搬**;拖放重排**不搬**(B3 固定三 tab) | `dockkit.module.css` + `TabPanel.tsx` 结构 |

| 工具协议 UI、轨迹数据、命令面板、分叉/评分、内置浏览器 | **不搬**(无对应数据或越界) | `ui-tool` / `ui-trajectory` / 等 |

**与 §3 主题方案的关系**:「全量搬」意味着 DSH 的**整套中性阶梯**进 Inkstone,不只是 accent——这是**方案 C 的变体**:壳层色全部走 DSH 阶梯(明暗两档),但**保留 10 个主题 id 作为 accent 配色**(不退役,不破坏 TUI 10 块契约与 v1.4「10 套」定稿)。即:**bg/text/border 由明暗决定,accent/语义色由主题决定**。四段带的"过渡色"随之退场——它和 DSH 阶梯不可兼得,维护者以"全量搬"表了态。

**代码层纪律(执行者必守)**:
1. `gui/package.json` **不得**新增任何 `@deepseek-ai/*` 依赖;`gui/src` **不得**出现 `import … from '@deepseek-ai/…'`;加一条守卫测试 `tests/unit/gui/no-dsh-imports.test.js` 读源文本断言。
2. 不复制 DSH 源文件:不允许 `.module.css` 或 `.tsx` 整文件拷入后改名。每个新文件是 Inkstone 原生写法(React + 现有 `workbench-state` reducer + 现有 i18n),类名沿用/扩展 Inkstone 既有命名(`.rail-* .cz-* .ev-* .th-*`),**不引入 `--dsw-*` / `--dsh-*` 变量名**。
3. 18 槽 `tokens.css` 契约不变(TUI 生成器 `gen-tui-theme.js` 正则 + 110 项闸门口径改为「2 明暗 × 11 对 + 10 accent × 4 对」);新增的 DSH 派生量(hover alpha / 描边 l1–l3 / 阴影 / 圆角 / 时长)全部落 `theme.css` 的 `[theme]` 别名块与 `:root`。
4. 文件头**不标 DSH 来源**(仓库不写参照来源属产品事实之外;设计参照记录只在本 spec 与 plan)。
5. CSS Modules:**引入**(Vite 零配置),新组件一律 `.module.css`;这是写法选择,不是引用 DSH。
