# Agent 分层记忆系统设计

> 类型:后端 / 内核 设计 spec
> 日期:2026-06-24
> 状态:已评审,待转实施计划
> 关联:[V3 路线图](../architecture/2026-06-24-v3-roadmap-design.md)(Phase C)

---

## 1. 设计理念

**人不是把世界原样存进脑子,而是把经历压缩成「以后怎么判断、怎么行动」的模型。** 记忆不是硬盘,经验不是日志,它更像一个不断更新的预测系统。

因此 agent 记忆系统不应是「聊天记录库」,而应**分层**,并且会**筛选、总结、遗忘、强化、更新**。最有价值的不是「记得多」,而是「**知道什么重要、知道何时调用、知道如何按反馈修正自己**」。

---

## 2. 人脑模型 → Agent 映射(总流水线)

```
人:   外界 → 感觉记忆 → 注意筛选 → 工作记忆 → 长期记忆 → 经验/判断模型
agent: 事件 → 原始日志 → 上下文筛选 → 工作上下文 → 分层记忆 → planner 派发策略
```

**关键洞察**:这条链的前半段项目已有——
- **原始日志(情景记忆)= 已有的事件时间线**(`src/sessions/event-log.js`,append-only + 哈希链)。这是 agent 的「海马体记录」,**不另建平行日志**。
- **注意筛选 + 工作记忆 = 上下文引擎**(`src/context/`,Phase B 升级为语义级)。工作记忆容量小是对的——按需取,不把全部记忆灌入。

---

## 3. 分层记忆架构

### 3.1 七层(落到具体存储 + 谁写谁读)

| 人类层 | Agent 存储 | 归属 | 谁写 | 谁读 |
|---|---|---|---|---|
| 情景记忆(何时何地何事) | 事件时间线 | **既有** | 系统自动 | 巩固时回放 |
| 语义记忆(知识/规则/概念) | 事实库 | **主记忆** | 子 agent 执行时 | 子 agent 执行时 |
| 偏好记忆(用户喜恶) | 偏好库 | **主记忆** | 子 agent / 用户 | 子 agent、planner |
| 程序记忆(验证有效的工作流) | 经验库 | **经验记忆** | 仅次 agent | planner 拆/派时 |
| 风险记忆(易错/需确认) | 风险库 | **经验记忆** | 仅次 agent | planner + 权限层 |
| 反思记忆(本次学到啥) | 反思缓冲 | **经验记忆** | 次 agent | 巩固为程序/风险后丢弃 |
| 情绪记忆(安全感/风险感) | 显著度/风险标记 | 横切 | 次 agent | 检索权重 + 权限层 |

自传记忆(我是谁)= persona/config,轻量,本设计不展开。

### 3.2 两套记忆系统,彻底分开

| | **主记忆系统**(已有) | **经验记忆系统**(新增) |
|---|---|---|
| 存什么 | 项目事实、用户偏好 | 次 agent 提炼的审核摘要 / 教训 / 优化建议 |
| 子类 | 语义记忆、偏好记忆 | 程序记忆、风险记忆、反思记忆 |
| 谁写 | 子 agent 执行时(`tools/builtin/memory.js`) | **只有次 agent**(提炼后) |
| 谁读 | 子 agent 执行时取事实 | **主 agent 的 planner**,下一轮拆/派时取 |
| 何时生效 | 一直 | **开关控制**(默认关,用户开) |
| 存哪 | 现有 memory 工具存储 | 独立目录,如 `.deepseek-code/v2/experience/` |
| 信任级别 | 高(事实) | 低(启发,带置信度) |

**为什么必须分开**:经验记忆可随时整体清空、降权、重置,而**不碰**项目事实;主 agent 读经验、子 agent 读事实,消费者不同;防止把审核噪音沉淀进事实库。

## 4. 巩固器 = 次 agent(海马体 + 前额叶)

一次经历不会自动变成经验,要复盘。对应人类经验形成链:

```
发生事件 → 注意重点 → 目标关联 → 解释原因 → 行动 → 反馈 → 形成模式 → 以后调用
   └───────────────── 这一整段 = 次 agent 干的活 ─────────────────┘
```

次 agent 在**任务边界**(不是执行中途)回放相关事件 → 写「反思」→ 把反复验证有效的提炼成「程序/风险记忆」→ 套三级分化 → 跌破三级即删。

**巩固时机 = 睡眠**:只在 turn/task 边界**异步**巩固,**离开关键路径**,不拖慢当前任务。

---

## 5. 三级分化制度(经验记忆的遗忘与强化)

### 5.1 三个等级(按 置信度 × 老化程度 综合打分)

| 级别 | 定义 | planner 检索权重 | 状态 |
|---|---|---|---|
| **一级 · 核心经验** | 高置信 + 近期反复验证有效 | 强影响(优先采纳) | 稳定 |
| **二级 · 候选经验** | 中置信 / 中等老化,验证有限 | 中影响(参考) | 试用期 |
| **三级 · 观察经验** | 低置信 / 偏旧 / 新加入未验证 | 弱影响(仅提示) | 观察期 |
| **低于三级** | 置信过低 / 太旧未强化 / 屡次误导 | —— | **及时删除** |

### 5.2 升降与淘汰

```
新经验 → 进【三级·观察】
   ├─ 被检索 + 下一轮审核证明有效(强化)→ 置信↑ → 升二级 → 再强化 → 升一级
   ├─ 久未强化(老化)→ 置信随时间衰减 → 逐级下降
   └─ 被审核判定误导 / 与新事实冲突 → 置信骤降 → 降级
                                          └─ 跌破三级阈值 → 立即删除(末位淘汰)
```

- **打分**:`score = f(置信度, 距上次强化时间, 累计验证次数)`,映射三级阈值 `T1 / T2 / T3`(初始值实施前再定)。
- **强化**:被采纳且次 agent 下轮审核确认有效 → 置信 +、验证次数 +。
- **削弱**:被审核判为误导,或被新事实推翻 → 置信 −。
- **老化**:不靠时间硬删,而是「久未强化 → 衰减 → 自然下沉」;活跃有用的经验靠反复强化留在高级别。

### 5.3 同类经验归并
- 语义相近的经验聚成一簇(复用 Phase B 语义检索)。
- 同簇内保留最高级那条,合并证据、累加验证次数;簇内跌破三级的副本直接删。
- 防止「同一条教训以不同措辞反复堆积」。

### 5.4 淘汰执行
- **写时即评**:每次次 agent 写入/强化,顺带重算该簇等级,跌破三级当场删。
- **周期清扫**:可选后台扫描,统一处理因老化下沉到三级以下的经验。
- 删除有日志(可追溯),且只动经验记忆,主记忆与原始日志不受影响。

## 6. 自主优化的两层

```
本次任务内(始终开):
   次 agent 审核摘要 → 主 agent 立即调整后续派发        简单、安全、可测

跨任务沉淀(开关,默认关):
   次 agent 提炼高价值教训 → 写入【经验记忆系统】
        → 新任务时 planner 检索相关经验 → 影响拆/派决策
```

**开关**:`autonomy.crossTaskLearning: off | on | gated`(默认 `off`,显式 opt-in)。
- `on`:自动沉淀。
- `gated`:沉淀前对高影响经验人工确认。

---

## 7. 防「伪经验」卫生措施

1. **三级分化 + 末位淘汰**(第 5 节):有用的反复强化升级长留,没用的老化下沉、跌破三级即删。
2. **置信度评分 + 老化衰减**:旧的、低置信的自动降权。
3. **去重 + 上限**:防同类教训反复堆积;设经验库总量上限。
4. **可追溯**:每条经验链回到产生它的 task/turn,可审计、可撤销。
5. **隔离即保险**:一键清空经验记忆,主记忆与原始日志毫发无伤。
6. **检索复用 Phase B**:planner 取经验用语义检索,而非全量灌入。

## 8. 五条人脑原则 → 机制

| 原则 | 机制 |
|---|---|
| **筛选** | 上下文选择器 + 注意力(Phase B 语义检索) |
| **总结** | 次 agent 提炼(原始事件 → 压缩成判断模型) |
| **遗忘** | 三级分化 + 末位淘汰(健康的遗忘是特性,不是缺陷) |
| **强化** | 被采纳且审核确认有效 → 置信↑ → 升级长留 |
| **更新** | 「重建而非回放」:新事实与旧经验冲突时,改写旧经验的含义,而非简单追加 |

---

## 9. 关键设计原则(相对人脑的改进)

1. **记忆是事件日志的「投影」而非副本**:所有长期记忆带指针回链到产生它的原始事件——派生物,不是真相本身。契合事件溯源基因,记忆可重算、可纠偏。
2. **可追溯是 agent 对人的优势**:人回忆丢失出处而产生偏见;agent 保留出处,源事件被重新解释时能反向修正经验。保留「重建」的力量,去掉偏见。
3. **情绪记忆 → 接权限层**:给记忆打「风险显著度」,高风险记忆既加大检索权重,又触发权限层人工确认。记忆与安全闸联动。
4. **巩固时机 = 睡眠**:只在 turn/task 边界异步巩固,绝不执行中途。
5. **遗忘要敢删**:设总量上限,跌破三级真删(只删经验记忆)。
6. **检索是「合成简报」非「贴原文」**:planner 取经验时合成贴合当前情境的判断简报,而非粘贴旧记录;用出处 + 置信度兜住虚构。

## 10. 与现有代码的集成点

| 关注 | 现有 | V3 动作 |
|---|---|---|
| 原始日志/情景记忆 | `sessions/event-log.js`(append-only + 哈希链) | 直接复用为情景记忆源,不新建 |
| 工作记忆 | `context/`(文件分层) | Phase B 升级语义级;按需检索喂工作上下文 |
| 主记忆(事实/偏好) | `tools/builtin/memory.js` | 细分语义记忆 + 偏好记忆 |
| 经验记忆 | 无 | **新增独立子系统**(目录 + schema),次 agent 写、planner 读 |
| 巩固器 | 无 | **次 agent**(Phase C)在任务边界异步巩固 |
| 风险标记 → 权限 | `tools/permissions/permission-engine.js` | 风险记忆的显著度触发人工确认 |

**落地分工**:经验记忆的**存储层**(目录、schema、读写 API)可在 Phase A 稳定化时先打底;**巩固逻辑 + 三级分化 + 开关**随 Phase C 一起。

## 11. reasoning_content 处理(踩坑)

- **不把 `reasoning_content` 当长期记忆保存**(V2 已对:`deepseek/usage-tracker.js` 抓取但标记 hidden、不入库)。
- 只保存次 agent 提炼后的「推理摘要 + 任务状态」。
- 原始 reasoning 留在事件时间线(原始日志)即可,经验记忆只存压缩后的判断模型。
