## 1. 独立预算契约 (Aggregate Request Budget Contract)

### 1.1 核心原则与架构分层
- **全局编排总预算**：由 `createRequestBudget({ maxTokens, maxModelCalls, fallbackTokensPerUnknown, executionId })` 创建，依托于 `RequestScope` 在编排请求生命周期内统一管理。
- **作用域绑定**：由 `src/index.js` 的 `routedSend` 在路由决策前预先创建全局 `rootBudget` 与 `baseScope`，确保分流阶段（`router`）的模型调用已直接在同一 `executionId` 账本中计量。当判定为 `orchestrate` 泳道时，直接继承该 `rootBudget` 作为编排总预算，并通过 `scope.bindGateway(modelGateway, { role, subtaskId })` 注入到所有编排参与者；若判定为 `single` 泳道，则普通单任务对话不挂载该编排总预算。
- **与局部 Limits 的兼容关系 (R7)**：
  - `orchestration.budget` 专属于多代理编排泳道（`decision.lane === "orchestrate"`）。
  - 普通单任务请求（`decision.lane === "single"`）绝不挂载 `orchestration.budget`，不干预其多轮工具调用循环（如读取文件后由模型再次作答），避免破坏普通对话的已有上限与稳定性。
  - 单任务请求仍遵守其自有的 `options.limits`（如 `maxTurnTokens`, `maxModelCalls`）。

### 1.2 预留与结算流程 (Reservation & Settlement)
1. **预留阶段 (`reserveCall`)**：
   - 预估消耗：出站前由 `estimateRequestTokens(request, options)` 计算本次请求的预估输入 + 输出 token 数。
   - 原子排他检查：`check(estimatedTokens)` 验证 `effective_tokens` 是否超限、调用次数是否超限。
   - 锁定额度：`reservedCalls += 1`, `reservedTokens += estimatedTokens`。
2. **发送确认 (`markStarted`)**：
   - 真实出站 HTTP 发起前调用：将预留调用名额原子转换为实际调用名额（`reservedCalls - 1`, `modelCalls + 1`）。
   - 网络故障不可退还：一旦发送开始，无论后续网络是否超时或断开，本次物理调用名额均不退还，防止服务商已扣费但本地账本漏记。
3. **结算阶段 (`settle`)**：
   - 释放预留 token：`reservedTokens = Math.max(0, reservedTokens - estimatedTokens)`。
   - 实际 token 记账：使用 `normalizeUsageTokens(usage)` 严格校验，有效则累加至 `tokens` 与角色对应账本；无效/缺失则计入 `unknownUsageAttempts`。
   - 幂等性：基于 `settledAttempts` 集合保障同一 `attemptId` 不发生二次重复计费。

## 3. 未知费用策略 (Unknown Usage Policy - R1, T01)

针对模型供应商可能返回缺失 usage、非有限数值或负数的情况：
1. **输入验证 (`normalizeUsageTokens`)**：
   - 接受非负有限的 `total_tokens`（`Number.isFinite(v) && v >= 0`，支持合法的零消耗 `0`），或从非负有限的 `prompt_tokens + completion_tokens` 计算总和。
   - 包含负值（如 `prompt_tokens: -50`）、NaN、Infinity 或缺失对象的响应一律判定为非法，返回 `null`。
2. **逐请求累计与有效 token 占额 (`effectiveTokens`)**：
   - 收到缺失或非法 usage 时，`unknownUsageAttempts` 计数递增。
   - 单次未知费用产生时，按 $\max(\text{fallbackTokensPerUnknown}, \text{estimatedTokens})$ 计入当前账本的累计未知占额 $\text{unknownUsageTokens}$。
   - 当前账本状态下的有效 token 占用：
     $$\text{effectiveTokens} = \text{tokens} + \text{reservedTokens} + \text{unknownUsageTokens}$$
   - 下一请求准入预留检查（`check(estimatedTokens)`）：验证 $\text{effectiveTokens} + \text{estimatedTokens} \le \text{maxTokens}$。
   - 默认每个未知请求保留有界保底占额 `fallbackTokensPerUnknown = 500`（或通过配置指定，并在快照中持久化记录）。
3. **跨进程与跨会话恢复契约 (T01 修复保证)**：
   - `unknownUsageTokens` 与 `fallbackTokensPerUnknown` 在 snapshot、序列化（`serializeOrchestrationState`）、反序列化、`budgetContinuation` 及 `makeResumedBudget` 全链路完整贯穿传递。
   - 新格式记录恢复后继承完整的未知占额负债（例如 4020 tokens 恢复后依然严格为 4020 tokens），确保恢复前后剩余配额拦截行为一致。
   - 旧记录若有未知请求、有有限 token 配额，却缺少可验证的完整未知占额，则阻断恢复并保留原记录。角色明细与未知次数只能提供部分历史信息，不能据此推导剩余可用配额；具体兼容边界见第 6 节。

## 4. Token 并发估算与预留契约 (Token Estimation & Concurrency - R2)

1. **真实网关估算策略 (`estimateRequestTokens`)**：
   - **结构化输入估算**：将出站请求中的消息正文（`content`、`reasoning_content`、`tool_calls` 序列化文本）与工具定义 schema（`tools` JSON 长度）字符数累加后，统一按 $\max(20, \lceil \text{totalChars} / 2.5 \rceil)$ 保守估算输入 token（不统计 `m.role` 字段本身）。
   - **输出估算**：优先采用明确写入出站 HTTP body 的服务端上限参数 `options.maxTokens`；未显式传入 HTTP `max_tokens` 时，采用各角色本地输出估值（router: 200, planner: 1000, worker: 1500, reviewer: 500, synthesizer: 800, 默认: 500）。
2. **并发争抢拦截**：
   - 在并发启动并行 Worker 时，出站前通过 `reserveCall` 原子增加 `reservedTokens` 与 `reservedCalls`。
   - 当多个 Worker 竞争剩余配额时，超出限额的 Worker 在发起出站 HTTP 之前被直接拦截（抛出 `BUDGET_EXCEEDED`），不存在先发 HTTP 后补扣超支。

## 5. 取消与 Dispose 生命周期契约 (Cancellation & Dispose Lifecycle - R3, R4, T02)

1. **分层作用域生命周期管理**：
   - **前台请求作用域 (`activeScopes: Set<RequestScope>`)**：`createKernel` 内部维护，由 `routedSend` 在其执行生命周期内挂载，并在 `finally` 离开时安全移除。
   - **编排活跃运行作用域 (`activeRunningScope`)**：`orchestrator` 内部维护，严格对应当前正在前台调度的编排轮次。
   - **后台异步任务作用域 (`backgroundScopes: Set<RequestScope>`)**：`orchestrator` 内部维护，追踪前台已返回后仍需在后台执行的异步操作（如 `kickConsolidation` 经验蒸馏）。
   - **暂停审批作用域**：处于等待审批的会话通过持久化机制（`pausedTurnStore` / recovery sidecar）落地保存，不纳入在途活跃中断集合，防止重启或中断销毁审批现场。
2. **中断通知 (`agent.interrupt()`)**：
   - 遍历 `activeScopes` 执行 `scope.abort("turn was interrupted")`。
   - 触发 `orchestrator.interrupt()` 中止正在运行的 `activeRunningScope` 以及 `backgroundScopes` 中的所有后台任务。
   - 触发 `runtime.interrupt()` 中止单任务运行。
3. **内核销毁 (`kernel.dispose()`)**：
   - 标记 `kernelDisposed = true`。
   - 遍历 `activeScopes` 执行 `scope.abort("kernel disposed")`，阻断在途网络与后续调度。
   - 触发 `orchestrator.interrupt()` 中止活跃编排与后台任务。
   - **注意**：`dispose()` 不调用 `runtime.interrupt()`，以保留磁盘上供跨进程重启恢复使用的 `pausedTurnStore` 与持久化 sidecars。
4. **轮内及最终汇总收口与取消终态 (T02 统一保证)**：
   - 每轮派发结束的 `finishPartial` 与最终 `orchestrator.finalize` 都处理汇总期间的 `AbortError` 或已取消 signal，并在 await 后再次检查取消，避免模型迟到返回覆盖取消状态。
   - `interrupt()` 或 `dispose()` 触发取消时保留已收集的子任务结果，由编排层返回 `{ status: "cancelled", outcome: "cancelled" }` 并发布一次 `orchestration:cancelled`，不发布 `orchestration:completed`。审批恢复后的轮内汇总遵守相同约定。
   - 未被取消时，预算不足或普通模型异常仍可由 synthesizer 降级为确定性摘要；轮内收口不吞掉其他意外异常。
5. **隔离工作区无迟到合并 (`dispatch-loop.js`)**：
   - 派发前、并行等待后、以及调用 `mergeSubtask` 前，严格检查 `signal.aborted`。
   - 若已被取消，已在隔离目录产出修改的 Worker 成果**绝不**合入主工作区。
   - 临时隔离目录经 `removeIso` 彻底清理，终态返回 `status: "cancelled"`。

## 6. 旧恢复记录迁移与兼容设计 (Recovery Migration & Compatibility - R5, R10, F06)

1. **门禁阻断与安全放行 (Legacy Gate & Safe Migration)**：
   - **有限配额且历史未记账**：若 sidecar 属于旧版本（缺少 `settledAttempts`、`unknownUsageAttempts` 元数据），且配置了有限配额（`quotaCalls` 或 `quotaTokens` 为有限数值），`orchestrationResumeGate` **fail-closed 严格拒绝恢复**（报错 `legacy unmetered budget: cannot safely verify remaining quota`），保留磁盘现场并防止配额重置失控。
   - **已有未知次数但金额不完整**：若 `quotaTokens` 为有限数值、`unknownUsageAttempts > 0`，且 `unknownUsageTokens` 缺失或不是有限正数，扫描门禁将记录标为 blocked；恢复或直接构造 continuation 抛出 `ORCH_RECOVERY_BLOCKED`，原因是 `unknown usage amount missing or invalid: cannot safely verify remaining token quota`。即使有 `byRole` 也不能放行，因为历史角色总额可能漏掉部分未知费用。拒绝时不消费两份 sidecar，不执行审批编辑或模型请求。
   - **新门禁的兼容边界**：未知次数为 0 的已计量记录不必补金额字段；含完整正数未知金额的新记录正常恢复。只有调用次数限制、没有 token 限制的已计量旧记录仍可沿用兼容估值，该估值不表示还原了全部历史金额，恢复后的 token 上限继续取原记录。
   - **未设配额历史记录**：若为无限额历史记录（`quotaCalls: null, quotaTokens: null`），允许恢复并标记 `legacyUnmetered = true`，按已完成 subtask 数量保守估算起步消费（每完成一个 subtask 预估至少 2 次调用），保留 `initialUnknownUsageAttempts = 1`。
2. **稳定恢复 ExecutionId 与 ByRole**：
   - 从持久化 sidecar 准确还原历史 `executionId`、`initialByRole` 与 `unknownUsageTokens`，经 `makeResumedBudget` 注入新预算实例，防止跨进程重启后丢失归属。
3. **有界 Settled Attempts 内存保护与去重时域**：
   - `settledAttempts` 采用有界滑动窗口（Set，容量上限 1000 条），淘汰最早条目，防止长期连续运行导致内存无界泄漏。其去重语义保障当前回合内重试、重跑与异常后处理的局部幂等性。
