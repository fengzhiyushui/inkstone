## 1. 独立预算契约 (Aggregate Request Budget Contract)

### 1.1 核心原则与架构分层
- **全局编排总预算**：由 `createRequestBudget({ maxTokens, maxModelCalls, fallbackTokensPerUnknown, executionId })` 创建，依托于 `RequestScope` 在编排请求生命周期内统一管理。
- **作用域绑定**：由 `src/index.js` 的 `routedSend` 在路由决策前预先创建全局 `rootBudget` 与 `baseScope`，确保分流阶段（`router`）的模型调用已直接在同一 `executionId` 账本中计量。当判定为 `orchestrate` 泳道时，直接继承该 `rootBudget` 作为编排总预算，并通过 `scope.bindGateway(modelGateway, { role, subtaskId })` 注入到所有编排参与者；若判定为 `single` 泳道，则普通单任务对话不挂载该编排总预算。
- **与局部 Limits 的兼容关系 (R7)**：
  - `orchestration.budget` 专属于多代理编排泳道（`decision.lane === "orchestrate"`）。
  - 普通单任务请求（`decision.lane === "single"`）绝不挂载 `orchestration.budget`，不干预其多轮工具调用循环（如读取文件后由模型再次作答），避免破坏普通对话的已有上限与稳定性。
  - 单任务请求仍遵守其自有的 `options.limits`（如 `maxTurnTokens`, `maxModelCalls`）。

### 1.2 预留与结算流程 (Reservation & Settlement)
1. **预留阶段 (`reserveCall`)**：
   - 预估消耗：出站前由 `estimateRequestTokens(request, options)` 计算本次请求的预估输入 + 输出 token 数。
   - 原子排他检查：`check(estimatedTokens)` 验证 `effective_tokens` 是否超限、调用次数是否超限。
   - 锁定额度：`reservedCalls += 1`, `reservedTokens += estimatedTokens`。
2. **发送确认 (`markStarted`)**：
   - 真实出站 HTTP 发起前调用：将预留调用名额原子转换为实际调用名额（`reservedCalls - 1`, `modelCalls + 1`）。
   - 网络故障不可退还：一旦发送开始，无论后续网络是否超时或断开，本次物理调用名额均不退还，防止服务商已扣费但本地账本漏记。
3. **结算阶段 (`settle`)**：
   - 释放预留 token：`reservedTokens = Math.max(0, reservedTokens - estimatedTokens)`。
   - 实际 token 记账：使用 `normalizeUsageTokens(usage)` 严格校验，有效则累加至 `tokens` 与角色对应账本；无效/缺失则计入 `unknownUsageAttempts`。
   - 幂等性：基于 `settledAttempts` 集合保障同一 `attemptId` 不发生二次重复计费。

## 3. 未知费用策略 (Unknown Usage Policy - R1)

针对模型供应商可能返回缺失 usage、非有限数值或负数的情况：
1. **输入验证 (`normalizeUsageTokens`)**：
   - 仅当 `prompt_tokens`, `completion_tokens`, `total_tokens` 均为非负有限数字（`Number.isFinite(v) && v >= 0`）时，才认可该 usage。
   - 包含负值（如 `prompt_tokens: -50`）、NaN、Infinity 或缺失对象的响应一律判定为非法，返回 `null`。
2. **有界有效 token 估算 (`effectiveTokens`)**：
   - 收到缺失或非法 usage 时，`unknownUsageAttempts` 计数递增。
   - 在 `exceeded()` 与 `check()` 中，采用保守估算计入有效 token 占用：
     $$\text{effectiveTokens} = \text{tokens} + \text{reservedTokens} + (\text{unknownUsageAttempts} \times \text{fallbackTokensPerUnknown}) + \text{estimatedTokens}$$
   - 默认每个未知请求保留有界占额 `fallbackTokensPerUnknown = 500`（或通过配置指定，并在快照中记录；跨进程恢复默认使用 500 或继承对应配置），杜绝网关在缺失 usage 情况下可无限免费调用的安全漏洞。

## 4. Token 并发估算与预留契约 (Token Estimation & Concurrency - R2)

1. **真实网关估算策略 (`estimateRequestTokens`)**：
   - **输入估算**：依据出站提示词正文字符数进行保守估算：
     $$\text{estimatedInput} = \max(20, \lceil \text{chars} / 2.5 \rceil)$$
   - **输出估算**：优先采用请求明确参数 `options.maxTokens`；未指定时采用各角色典型输出上限（router: 200, planner: 1000, worker: 1500, reviewer: 500, synthesizer: 800, 默认: 500）。
2. **并发争抢拦截**：
   - 在并发启动并行 Worker 时，出站前通过 `reserveCall` 原子增加 `reservedTokens`。
   - 当多个 Worker 竞争剩余配额时，超出限额的 Worker 在发起出站 HTTP 之前被直接拦截（抛出 `BUDGET_EXCEEDED`），不存在先发 HTTP 后补扣超支。

## 5. 取消与 Dispose 生命周期契约 (Cancellation & Dispose Lifecycle - R3, R4)

1. **活跃作用域追踪 (`activeScopes`)**：
   - `createKernel` 内部维护 `activeScopes: Set<RequestScope>`，追踪当前内核所有正在运行或暂停的请求作用域。
   - `routedSend` 进入时登记 scope，必须 `await` 实际任务生命周期结束（包括 single 和 orchestrate），在 `finally` 块中从 `activeScopes` 移除。
2. **中断通知 (`agent.interrupt()`)**：
   - 遍历 `activeScopes` 执行 `scope.abort("turn was interrupted")`。
   - 触发 `orchestrator.interrupt()` 中止正在运行的 `activeRunningScope` 及所有处于 `orchPaused` 的 scope。
   - 触发 `runtime.interrupt()` 中止单任务运行。
3. **内核销毁 (`kernel.dispose()`)**：
   - 标记 `kernelDisposed = true`。
   - 遍历 `activeScopes` 执行 `scope.abort("kernel disposed")`，阻断在途网络与后续调度。
   - 触发 `orchestrator.interrupt()` 中止活跃编排。
   - **注意**：`dispose()` 不调用 `runtime.interrupt()`，以保留磁盘上供跨进程重启恢复使用的 `pausedTurnStore` 与持久化 sidecars。
4. **隔离工作区无迟到合并 (`dispatch-loop.js`)**：
   - 派发前、并行等待后、以及调用 `mergeSubtask` 前，严格检查 `signal.aborted`。
   - 若已被取消，已在隔离目录产出修改的 Worker 成果**绝不**合入主工作区。
   - 临时隔离目录被直接安全清理，终态返回 `status: "cancelled"`。

## 6. 旧恢复记录迁移与兼容设计 (Recovery Migration & Compatibility - R5, R10, F06)

1. **门禁阻断与安全放行 (Legacy Gate & Safe Migration)**：
   - **有限配额且历史未记账**：若 sidecar 属于旧版本（缺少 `settledAttempts`、`unknownUsageAttempts` 元数据），且配置了有限配额（`quotaCalls` 或 `quotaTokens` 为有限数值），`orchestrationResumeGate` **fail-closed 严格拒绝恢复**（报错 `legacy unmetered budget: cannot safely verify remaining quota`），保留磁盘现场并防止配额重置失控。
   - **未设配额历史记录**：若为无限额历史记录（`quotaCalls: null, quotaTokens: null`），允许恢复并标记 `legacyUnmetered = true`，按已完成 subtask 数量保守估算起步消费（每完成一个 subtask 预估至少 2 次调用），保留 `initialUnknownUsageAttempts = 1`。
2. **稳定恢复 ExecutionId 与 ByRole**：
   - 从持久化 sidecar 准确还原历史 `executionId` 与 `initialByRole`，经 `makeResumedBudget` 注入新预算实例，防止跨进程重启后丢失归属。
3. **有界 Settled Attempts 内存保护与去重时域**：
   - `settledAttempts` 采用有界滑动窗口（Set，容量上限 1000 条），淘汰最早条目，防止长期连续运行导致内存无界泄漏。其去重语义保障当前回合内重试、重跑与异常后处理的局部幂等性。
