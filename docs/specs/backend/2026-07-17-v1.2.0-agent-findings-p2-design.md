## 问题与目标

在不动内核核心契约的前提下完成三项：grep 双预算超时、shell 子进程 env 白名单、仓库卫生易项（原型迁移、测试目录合并、模型名可配、删死 facade、文档回写）。#8 / #9.3 / #9.6 / #10 明确不做。

## 决策

| 决策点 | 选择 | 否决项 | 理由 |
|---|---|---|---|
| grep 超时 | 每文件 + 总预算，成功返回 + metadata | 抛超时异常 | 不打断正常搜索语义 |
| shell env | 白名单继承，不放行代理 | 全量继承 / 放行 proxy | 密钥面优先 |
| 模型名 | `config.models.{act,think,fim}` | 继续硬编码 | 可切换且默认不变 |
| 用户配置面 | 不开 grep 超时 / env allowlist | 一并配置化 | 收窄本轮风险 |

## 设计

### grep 超时

`createGrepTool({ now, totalTimeoutMs, perFileTimeoutMs })`，默认总 10000ms、每文件 2000ms。协作检测：文件前查总预算，行循环定期查双预算。单文件超时跳过并计数；总预算尽则返回已有 matches。metadata：`matches`、`timed_out`、`timed_out_scope: file|total|null`、`files_skipped_timeout`、`files_searched`。非法 pattern 仍按构造错误上抛。不换外部正则引擎。

### shell env 白名单

`buildChildEnv(baseEnv, { allowExtra })` + `runProcess(..., { env })`。白名单：`PATH`、Windows 系统键、用户/临时目录、区域变量。不放行密钥类、`HTTP(S)_PROXY`/`NO_PROXY`/`ALL_PROXY`、`NODE_OPTIONS`。`allowExtra` 仅供测试。依赖代理/密钥 env 的命令可能失败，属有意收紧。
