## 3. #6 grep 超时

### 3.1 现状

[`src/tools/builtin/grep.js`](../../../src/tools/builtin/grep.js):`new RegExp(params.pattern)` 后对工作区文本文件逐行 `regex.test`,无执行时间上限。

### 3.2 机制

| 项 | 约定 |
|----|------|
| 默认总预算 | `10000` ms |
| 默认每文件预算 | `2000` ms |
| 工厂注入 | `createGrepTool({ now, totalTimeoutMs, perFileTimeoutMs })`;生产默认 `Date.now`,阈值用上表默认 |
| 协作检测点 | 每文件开始前检查总预算;文件内按行循环中定期(每行或每 N 行,N 取小常数如 64)检查每文件预算与总预算 |
| 引擎 | 仍用 JS `RegExp`;不做完整静态 ReDoS 分析 |
| 用户 config | 本版不暴露 grep 超时配置项 |

### 3.3 超时语义(对外)

**成功返回 + metadata 标记**,不把超时当作未捕获异常抛出(非法 `pattern` 的 `RegExp` 构造错误仍按现网错误路径):

- `content`:已收集到的 matches 文本(截断/拼接规则与现网一致)。
- `metadata` 至少包含:
  - `matches: number`
  - `timed_out: boolean` — 曾发生每文件跳过或总预算用尽则为 `true`
  - `timed_out_scope: "file" | "total" | null` — 若总预算用尽为 `"total"`;若仅有文件级跳过、总未用尽可为 `"file"`;未超时为 `null`
  - `files_skipped_timeout: number`
  - `files_searched: number`(已开始处理的文件数,含超时跳过的文件)

行为:

1. **单文件超时、总预算未尽:** 跳过该文件,`files_skipped_timeout++`,继续下一文件。
2. **总预算用尽:** 立即停止搜索,返回已有 matches,`timed_out: true`,`timed_out_scope: "total"`。
3. 读文件失败:保持现网 `continue`。

### 3.4 测试

- 注入 `now`:第一文件触发每文件超时 → skip;第二文件仍被搜索。
- 总预算在文件间耗尽 → 不再处理后续文件。
- 正常 pattern + 小夹具:matches 与无超时逻辑一致。
- 非法 pattern:行为与现网一致(错误向上)。

### 3.5 非目标

不换外部正则引擎;不改 `max_matches` 默认;不做用户级超时配置 UI。

## 4. #7 shell 子进程 env 白名单

### 4.1 现状

[`src/security/shell-policy.js`](../../../src/security/shell-policy.js) `runProcess` 未传 `env`,子进程继承完整 `process.env`。

### 4.2 机制

新增(或等价导出):

```text
buildChildEnv(baseEnv = process.env, { allowExtra = [] } = {}) → plain object
runProcess(argv, { cwd, timeoutMs, env } = {})
  → spawn(..., { env: env ?? buildChildEnv(process.env), shell: false, ... })
```

生产路径:`createShellTool` → `runProcess` **始终**默认走 `buildChildEnv`;测试可注入完整 `env` 或依赖 `allowExtra`。

### 4.3 白名单键

拷贝下列键(在 Windows 上对 `process.env` 做**大小写不敏感**解析,按实际键名写回):

| 类别 | 键 |
|------|-----|
| 路径 | `PATH` |
| Windows | `PATHEXT`, `SystemRoot`, `COMSPEC`, `WINDIR` |
| 用户目录 | `HOME`, `USERPROFILE`, `HOMEDRIVE`, `HOMEPATH` |
| 临时目录 | `TMP`, `TEMP`, `TMPDIR` |
| 区域 | `LANG`, `LC_ALL`, `LC_CTYPE`, `LANGUAGE` |

**不放行(示例,白名单已隐含排除):**  
`DEEPSEEK_*`、匹配密钥习惯的键、`HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` / `ALL_PROXY`(及小写)、`NODE_OPTIONS`、`AWS_*`、`GITHUB_TOKEN` 等。

`allowExtra`:仅函数参数,供单测;本版**不**暴露用户 config。

### 4.4 不变部分

argv-only、`shell: false`、超时、输出截断、`normalizeShellParams` 语义保持。

### 4.5 测试

- 父进程含假 `DEEPSEEK_API_KEY` / 其它 `*_API_KEY`:子进程读不到。
- 父进程含 `HTTP_PROXY`:子进程无该键。
- `PATH`(或 Windows `Path`)仍在,简单命令可执行。
- `allowExtra: ['FOO']` 时 `FOO` 可进入。
- 现有 shell 超时/截断/argv 测试不回归。

### 4.6 可接受兼容性损失

依赖代理 env 或密钥 env 的子进程命令本版可能失败 — 有意为之。
